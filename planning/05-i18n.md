# 05 - Internationalisation

## Strategy

- English is the source of truth. Content is written and stabilised in English first.
- Spanish is translated per part once that part is stable, not after the whole course.
- Target Spanish: neutral Latin American, using **tú** (informal, common in modern
  technical education). Decision recorded in the glossary.
- Starlight handles locale routing, the language picker, built-in UI strings, and
  fallback to English for untranslated pages.

## What gets translated

| Item                     | Where                             | Notes                                           |
| ------------------------ | --------------------------------- | ----------------------------------------------- |
| Lesson content           | `src/content/docs/es/`            | Mirrors the English tree, same slugs            |
| Sidebar labels           | `astro.config.mjs` `translations` |                                                 |
| Custom component strings | `src/content/i18n/es.json`        |                                                 |
| Diagrams with text       | `src/assets/es/`                  | Avoid where possible                            |
| Code examples            | Not translated                    | Code, identifiers, and comments stay in English |
| Case study data          | Already Spanish-flavoured         | Column names stay as they are in the dataset    |
| Prompt examples          | Translated                        | Spanish learners should see Spanish prompts     |

Decision on code: identifiers and comments stay in English because that is how
professional code is written and what learners will see in documentation. Spanish
lessons explain this explicitly once.

## Staleness tracking

Each Spanish page stores `sourceHash`, the hash of the English file it was translated
from. `scripts/check_translations.py`:

1. Computes the current hash of each English page.
2. Lists Spanish pages whose `sourceHash` does not match (stale) and English pages with no
   Spanish counterpart (missing).
3. Prints a report in CI as a warning, and can output a Markdown table for a tracking issue.

The hash covers the body only, so frontmatter edits like `lastVerified` do not trigger
false staleness.

## Translation workflow

1. Part is marked stable in English.
2. LLM-assisted first draft, with `planning/glossary.md` and `04-content-guide.md` in the
   prompt. Frontmatter set to `translationStatus: machine`.
3. Human review for accuracy, terminology, and natural phrasing. Set to `reviewed`.
4. Merge. Pages are published as soon as they are machine-translated, with a visible
   notice: "This page was translated automatically and is pending review." The notice
   disappears when `translationStatus` becomes `reviewed`. Rendered by a `<TranslationNotice>`
   check in the page layout, driven by frontmatter.

The translation process itself can serve as a worked example in Part 10.
