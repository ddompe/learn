## Why this matters

Lesson 1.4 showed that paths differ between systems and that a relative path depends on
where you are standing. Hand-built text paths such as `"C:\\Users\\..."` break the moment
a colleague runs the program. The `pathlib` module solves this: you describe a path in
pieces, and it writes it correctly for the system.

## Path objects

```text
from pathlib import Path

data_dir = Path("data")
sales = data_dir / "cafe_central_sales.csv"
```

The `/` operator joins pieces with the right separator for the system. Useful parts and
actions:

| Expression             | Meaning                         |
| ---------------------- | ------------------------------- |
| `path.name`            | File name with extension        |
| `path.suffix`          | Extension, such as `.csv`       |
| `path.parent`          | The folder that holds it        |
| `path.exists()`        | Whether it is there             |
| `path.read_text(...)`  | Read the whole file as text     |
| `path.write_text(...)` | Write text to the file          |
| `folder.glob("*.csv")` | Find files that match a pattern |

Always pass `encoding="utf-8"` when reading or writing text, so accents survive (lesson 1.7).

## Find files relative to the script

`Path(__file__)` is the location of the running script. Starting from it, you can reach
other files whatever the current folder is.

## Common mistakes

- **Typing paths as text with backslashes.** Use `Path` and `/`.
- **Relying on the current folder.** Anchor paths to `__file__`.
- **Forgetting the encoding.** Add `encoding="utf-8"`.
- **Overwriting an input file.** Write results to a different file or folder.
- **Using absolute paths from your own machine in shared code.**
