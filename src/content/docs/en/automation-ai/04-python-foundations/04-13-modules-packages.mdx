## Why this matters

You do not write everything yourself. Reading CSV files, counting, handling dates, and
working with tables are all done by code that others wrote. In Python, you bring that code
in with `import`. Knowing where it comes from, and how to add it safely, is part of
working well.

	package she installs.
</CaseStudy>

## Modules and packages

A **module** is a file of Python code that you can reuse. A **package** is a collection
of modules, distributed through a registry (lesson 3.8).

- The **standard library** is the modules that come with Python: `csv`, `pathlib`,
  `decimal`, `datetime`, `collections`, and many more. No installation is needed.
- **Third-party packages** are installed from PyPI with `uv add`: for example `pandas`.

## Importing

```text
import csv
from collections import Counter
import pandas as pd
```

- `import csv` makes the module available as `csv`.
- `from collections import Counter` takes one name from a module.
- `import pandas as pd` gives a short nickname. `pd` is the universal nickname for pandas.

## Adding a package safely

1. Decide whether you need it. Does the standard library already do the job?
2. Check the exact name on PyPI (lesson 3.8): maintainers, release history, links.
3. Run `uv add name` inside the project.
4. Commit `pyproject.toml` and `uv.lock`.

If you get `ModuleNotFoundError`, the package is not in the environment you are using. Run
the program with `uv run`, and check that the package is in `pyproject.toml`.

## Common mistakes

- **Naming your own file like a module.** A file called `csv.py` hides the real `csv`.
- **Installing with pip.** Use `uv add`.
- **Importing everything with `*`.** It hides where names come from.
- **Adding a package for a tiny job.** Each one is a dependency to maintain.
- **Not committing the lock file.**
