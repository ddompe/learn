## Why this matters

A **notebook** mixes code, results, and notes in one document. You run the code in small
pieces called cells and see the result below each. This is ideal for exploring data,
because you see the effect of each step. It is also where many beginners get confused,
so it helps to learn the rules first.

<CaseStudy>
	Daniela wants to look at the sales file step by step: the columns first, then
	a few rows, then the categories. A notebook lets her see each result before
	moving on.
</CaseStudy>

## Cells, kernels, and order

- A **cell** is a block of code (or text) that you run on its own.
- A **kernel** is the running Python process behind the notebook. It keeps variables in
  memory between cells.
- Cells can be run in **any order**, and the kernel remembers what ran, not the order on the page.

That last point causes the classic trap: you run cell 3, then cell 1, then cell 2, and
your notebook shows results that no one can reproduce from top to bottom.

## Set it up in VS Code

1. Install the **Jupyter** extension (from the Microsoft publisher).
2. In your project, add the kernel package: `uv add --dev ipykernel`.
3. Create a notebook with the command palette: **Create: New Jupyter Notebook**.
4. At the top right, choose **Select Kernel**, then the Python environment in your
   project's `.venv`.

Write code in a cell and run it with the triangle, or press **Shift+Enter**.

## A notebook-style script

You can also write cells inside an ordinary `.py` file, marking each with `# %%`. With
the Jupyter extension, VS Code shows **Run Cell** above each one. This keeps the file
readable by Git and by any Python.

## Habits that keep notebooks honest

1. **Restart and run all** before you trust a result. This clears the memory and runs
   every cell in order.
2. Keep cells short and in logical order.
3. Do not depend on a cell that is far below.
4. Name things clearly. Ask what each cell needs from earlier ones.

### Your turn

Why does running only the third cell in a fresh kernel fail?

<Checkpoint question="Show the answer">
	It uses the variable `rows`, which is made by an earlier cell. A fresh kernel
	has not run that cell, so the name does not exist. The error is `NameError`.
</Checkpoint>

## Common mistakes

- **Running cells out of order.** Use Restart and Run All to check.
- **Hidden state.** A variable deleted from the code can still exist in memory.
- **Choosing the wrong kernel.** Packages seem to be missing. Select the project's `.venv`.
- **Committing a notebook with large outputs.** It makes Git history noisy.
- **Using a notebook for the final automation.** See lesson 4.7.
