## Why this matters

A notebook is a great workbench and a poor factory. Exploring is its strength. But a
notebook is awkward to run every month on its own, to test, or to review in Git. The
usual path is to explore in a notebook, then move the working code into a script.

<CaseStudy>
	Daniela has explored the sales file in a notebook. Now she wants it to run
	every month without her. That is the moment to graduate to a script.
</CaseStudy>

## Which one to use

| Question                        | Notebook | Script                  |
| ------------------------------- | -------- | ----------------------- |
| Exploring an unfamiliar file?   | Yes      | Possible                |
| Need to see each step's result? | Yes      | Add prints              |
| Will it run again, unattended?  | No       | Yes                     |
| Needs tests?                    | Hard     | Easy                    |
| Easy to review in Git?          | Noisy    | Clean                   |
| Sharing the story with others?  | Good     | Needs a report (Part 8) |

## Converting notebook code into a script

Compare the notebook-style version with the script version of the same idea.

Notebook-style, from lesson 4.5:

<Example file="part04/05_explore.py" />

As a script:

<Example file="part04/07_script.py" />

What changed:

1. The repeated steps became a **function**, `read_rows`, that you can test.
2. The code that runs when you start the file moved into `main()`.
3. `if __name__ == "__main__":` means "only run `main()` when this file is started
   directly". Another file can import the functions without running them.
4. Constants like the file location moved to the top, with an upper-case name.

## Common mistakes

- **Automating a notebook directly.** Convert it to a script first.
- **Leaving exploration code in the script.** Keep it short and focused.
- **Rewriting everything.** Move working code, then improve it.
- **Forgetting `if __name__ == "__main__":`.** Importing the file would run the whole thing.
- **Skipping tests after the move.** Add them as soon as there are functions (lesson 3.9).

## Check yourself

<Checkpoint question="Why is a script easier to test than a notebook?">
	Its logic sits in functions that tests can import and call with known inputs.
</Checkpoint>

<Checkpoint question="What does the line that starts with if __name__ do?">
	It runs the code under it only when the file is started directly, not when it
	is imported.
</Checkpoint>

<Checkpoint question="When is a notebook the better tool?">
	When exploring an unfamiliar file and looking at each step's result.
</Checkpoint>
