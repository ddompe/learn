## Why this matters

A **function** is a named, reusable piece of code. It takes input, does a job, and gives
back a result. Functions are what make programs readable, testable, and reusable. They
are also what you will ask an assistant to write, and what you will check with tests.

<CaseStudy>
	The amounts in the sales file come in three styles: `1500`, `1400.50`, and
	`$1500,50`. The dates come in three styles too. Daniela needs one function for
	each that turns any style into a clean value.
</CaseStudy>

## Anatomy of a function

```text
def parse_amount(text):
    ...
    return value
```

- `def` starts the definition, followed by the name and **parameters** in brackets.
- The indented lines are the **body**.
- `return` hands a result back to the code that called the function.

You **call** a function by writing its name with the input, the **argument**:
`parse_amount("$1500,50")`.

## Return, not print

`print` shows something on the screen. `return` gives the value back so that other code
can use it. A function that only prints cannot be used in a calculation or a test. In
general, functions should return values, and only the outer layer of a program prints.

## The two parsers

<Example file="part04/12_functions.py" />

`parse_amount` removes the `$` and turns a comma decimal separator into a point, then makes an exact `Decimal`.
`parse_date` looks at how the text is written and splits it accordingly. The slash style
`13/01/2024` is read day first, because the data contains `13/01/2024`, which could not be
month first.

Notice the docstring, the text in triple quotes. It says what the function does. Good
functions have a clear name and a short docstring.

## Common mistakes

- **Printing instead of returning.** The caller gets `None`.
- **Doing too much in one function.** One function, one job.
- **Hidden assumptions.** Write them in the docstring, as with the day-first dates.
- **Using global variables inside functions.** Pass what you need as parameters.
- **No tests.** A function that cleans data needs tests with tricky inputs.

## Check yourself

<Checkpoint question="What is the difference between print and return?">
	`print` shows text on the screen. `return` gives a value back to the caller so
	it can be used.
</Checkpoint>

<Checkpoint question="What is a parameter?">
	A name in the function definition that receives the input when the function is
	called.
</Checkpoint>

<Checkpoint question="Why write a docstring?">
	It explains what the function does and its assumptions, for readers and for
	yourself later.
