## Why this matters

In Excel, a cell can look like a number and secretly be text, and then a sum comes out
wrong. Python has the same issue, but it is stricter and clearer about it. The first
thing to know about any value is its **type**: what kind of thing it is, and therefore
what you can do with it.

<CaseStudy>
	Everything that Daniela reads from the sales CSV arrives as text, including
	the amounts. If she adds two amounts without converting them, she joins the
	text instead of adding the numbers.
</CaseStudy>

## Variables

A **variable** is a name that points to a value. You create it with `=`:

```text
amount = 2200
```

Read it as "let `amount` be 2200", not as an equation. You can change it later. Choose
names that say what the value is: `amount` is better than `x`.

## The common types

| Type    | Python name | Example           | Use                             |
| ------- | ----------- | ----------------- | ------------------------------- |
| Text    | `str`       | `"jugo"`          | Words, IDs, file contents       |
| Integer | `int`       | `7`               | Counts                          |
| Float   | `float`     | `7.5`             | Measurements, with small errors |
| Decimal | `Decimal`   | `Decimal("7.50")` | Exact money (lesson 1.8)        |
| Boolean | `bool`      | `True`, `False`   | Yes or no answers               |
| Nothing | `NoneType`  | `None`            | "No value here"                 |

`type(value)` tells you the type.

## Types decide what operations mean

<Example file="part04/08_types.py" />

The line `Text plus text` shows the trap: `"2200.00" + "2200.00"` gives
`2200.002200.00`. For text, `+` means "join". After converting to `Decimal`, the same `+`
means "add", and the result is `4400.00`.

<Mermaid
	diagram={`flowchart LR
  A["Text from the file: '2200.00'"] -->|"Decimal(...)"| B["Exact number: 2200.00"]
  B --> C["Arithmetic works"]`}
/>

To convert, use the type's name as a function: `int("7")`, `float("7.5")`,
`Decimal("7.50")`, `str(7)`.

If the text is not valid for the type, Python stops with an error, which is better than
silently adding wrong numbers.

## Common mistakes

- **Doing arithmetic on text.** Convert first.
- **Using floats for money.** Use `Decimal` (lesson 1.8).
- **Using a name that is too short or unclear.**
- **Reusing a variable name for something else.** It makes code harder to follow.
- **Mixing `=` and `==`.** One assigns, and the other compares (lesson 4.11).
