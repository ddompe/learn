## Why this matters

Tutorials, blog posts, and colleagues often use notebooks in other places. You do not
need to work in them, but you should recognise them, follow their examples, and know
what you give up. The course workflow stays in VS Code, but here is the wider picture.

<CaseStudy>
	A colleague sends Daniela a link to a notebook on a cloud service, with a
	note: "Just upload the sales file." Before she does, she needs to ask where
	the data will go.
</CaseStudy>

## The classic Jupyter

**Jupyter** is the original notebook system. The classic **JupyterLab** runs in a web
browser, with the Python process on your computer or on a server. The notebook files end in
`.ipynb`, and they are the same format that VS Code opens.

If you want to try it with uv, one command starts it from your project:

```text
uv run --with jupyterlab jupyter lab
```

It opens a page in your browser. The local data stays on your machine.

## Google Colab

**Google Colab** is a notebook that runs on Google's servers. You open it in a browser
with a Google account. There is nothing to install, which is convenient. But:

- Your **code and data** go to Google's cloud. Do not upload customer data or anything
  confidential without approval (lesson 2.8).
- The session is **temporary**. Files you upload disappear when the session ends.
- The packages and their **versions** may differ from your project, so results may differ.

## marimo

**marimo** is a newer notebook that stores the notebook as a plain Python file and
re-runs dependent cells automatically, which removes the out-of-order problem. It is a
bonus to try later. The course does not depend on it.

## Following an example written for another tool

When a tutorial says:

- "Run `!pip install package` in a cell": use `uv add package` in your terminal instead.
- "Upload the file to the left panel": put the file in your project's data folder.
- "Mount your Google Drive": read the file from a local folder.

## Common mistakes

- **Uploading company data to a cloud notebook without approval.**
- **Assuming Colab results will match your project.** Versions may differ.
- **Mixing `pip` into a uv project.** Use `uv add`.
- **Forgetting that a Colab session is temporary.** Save your results.
- **Using a different tool for every example.** It multiplies the setup problems.
