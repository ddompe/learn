## Why this matters

This lesson uses everything from Part 4 in one small, real tool. It reads the messy sales
file, removes the duplicate lines, cleans the categories and amounts, and prints a total
for each category. The functions are small, and each has a test.

## The script

<Example file="part04/16_sales_summary.py" />

Read it from the top:

- `parse_amount` and `simplify` are the cleaners from lessons 4.12 and 4.9.
- `read_sales` uses the `csv` module to read rows as dictionaries, by column name (lesson 4.13).
- `remove_duplicates` keeps the first copy of each identical row, using a set (lesson 4.10).
- `totals_by_category` loops over the rows and adds each amount to its category total (lesson 4.11).
- `main` ties them together and prints. Only `main` prints. The others return values.

The output shows 246 rows read and 240 after duplicates, then a total for each category.
Because `simplify` merges `Café`, `cafe`, and `café`, there are five categories, not nine.

## The tests

The tests check each function on its own, with answers worked out by hand.

<Example file="part04/test_16_sales_summary.py" />

- `test_parse_amount_handles_all_three_formats` covers the three styles.
- `test_simplify_merges_spelling_variants` checks the category merge.
- `test_remove_duplicates_keeps_first_copy` uses a tiny list.
- `test_totals_by_category_adds_exactly` checks exact decimal arithmetic.
- `test_real_file_has_240_unique_rows` checks the real file, and ties back to lesson 0.3: 246 lines, 240 unique.

Run the tests with:

```text
uv run pytest
```

## Common mistakes

- **Writing the whole script before running anything.** Build and run it in small steps.
- **Tests that repeat the code.** Use expected values worked out by hand.
- **Trusting the totals without a spot check.**
- **Mixing printing and logic.** Keep the logic in functions that return values.
- **Forgetting that fixing categories is a choice.** Document your rule.

## Check yourself

<Checkpoint question="Why do only main() and not the other functions print?">
	Functions that return values can be tested and reused. Printing in one place
	keeps the logic clean.
</Checkpoint>

<Checkpoint question="Why is the number of categories five, not nine?">
	The cleaning step merges the spelling variants, such as Café, cafe, and café.
</Checkpoint>

<Checkpoint question="How do you know the totals are right?">
	Tests with hand-worked values, plus a manual spot check of one category
	against the CSV.
</Checkpoint>
