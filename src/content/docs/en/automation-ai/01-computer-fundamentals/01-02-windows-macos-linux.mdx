## Why this matters

You may work in a team where one person uses Windows, another uses a Mac, and the
servers run Linux. A file or a script that works on your machine can fail on a
colleague's for reasons that have nothing to do with its content. The reasons are small
differences between operating systems. Knowing them saves hours.

<CaseStudy>
	Daniela uses Windows. The owner's analyst, Mateo, uses a Mac. When Daniela
	sends Mateo a script that opens `C:\Users\Daniela\Documents\sales.csv`, it
	fails. The path is valid on her laptop and meaningless on his.
</CaseStudy>

## The three families

- **Windows** is the most common on business desktops.
- **macOS** runs on Apple computers.
- **Linux** is free and open source. You rarely use it on a desktop at work, but most
  servers and cloud services run on it. Many tools you will meet were built there first.

macOS and Linux share a common ancestry, so they behave alike in many ways. Windows
is the odd one out.

## Four differences that bite

### 1. Path separators and drive letters

Windows writes paths with a backslash and starts with a drive letter, as in
`C:\Users\Daniela`. macOS and Linux use a forward slash and no drive letters, as in
`/Users/daniela`. Lesson 1.4 covers paths in detail.

### 2. Line endings

A text file marks the end of each line with invisible characters. Windows uses two
(carriage return plus line feed). macOS and Linux use one (line feed). Most modern tools
handle both, but old tools or strict checks sometimes show strange symbols or extra
blank lines.

### 3. Case sensitivity

On Linux, `Sales.csv` and `sales.csv` are two different files. On Windows, and by default
on macOS, they are the same file. A script that works on your laptop can fail on a Linux
server because of a capital letter.

### 4. Permissions

Operating systems control who may read, change, or run each file. Company laptops often
block installing software without administrator rights. Part 4 teaches tools that work
within that limit.

## Common mistakes

- **Writing a path with a drive letter in code you share.** It only works on your machine.
- **Assuming capital letters do not matter.** They matter on Linux, so be consistent.
- **Believing the OS is the only difference.** Installed software and its versions differ too.
- **Trying to work around company restrictions.** If you cannot install something, ask IT
  or use the approach in Part 4 that does not need administrator rights.
