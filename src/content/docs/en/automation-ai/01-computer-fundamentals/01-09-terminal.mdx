## Why this matters

A **terminal** is a window where you type instructions to the computer instead of
clicking. It looks old-fashioned, but nearly every professional tool in the rest of the
course is run from it. It is also precise: a command you type can be pasted into an
email, repeated tomorrow, or run by a script.

The terminal is not dangerous when you know what you type. In this lesson you only look
around. You will not change or delete anything.

<CaseStudy>
	Daniela wants to check the Café Central folder without opening any program. In
	the terminal she lists the files, then prints the first lines of the sales
	file. It takes seconds.
</CaseStudy>

## What a terminal is

A terminal shows a **prompt**: a short text that says the computer is waiting for you.
You type a **command**, press Enter, and the computer prints the **output**.

The program that reads your commands is the **shell**. On Windows it is usually
**PowerShell**. On macOS it is **zsh**. They look different, but the basics match.

In this course, commands are shown with a symbol at the start of the line. `PS>` marks
PowerShell and `$` marks macOS. You type everything after the symbol, not the symbol.

## Open a terminal

<OsTabs>
  <Fragment slot="windows">
Press the **Windows** key, type `PowerShell`, and press Enter. A blue or black window
opens with a prompt such as `PS C:\Users\Daniela>`.
  </Fragment>
  <Fragment slot="macos">
Press **Command+Space**, type `Terminal`, and press Enter. A window opens with a prompt
ending in `%`.
  </Fragment>
</OsTabs>

The text before the symbol shows where you are. That is your **current folder**, which
you met in lesson 1.4.

## Four commands to look around

<OsTabs>
  <Fragment slot="windows">
```text
PS> pwd
PS> ls
PS> cd Documents
PS> cd ..
```
  </Fragment>
  <Fragment slot="macos">
```text
$ pwd
$ ls
$ cd Documents
$ cd ..
```
  </Fragment>
</OsTabs>

- `pwd` prints the current folder.
- `ls` lists the files and folders in it.
- `cd Documents` moves into the folder `Documents`.
- `cd ..` moves up one folder.

None of these change a file. If you get lost, `cd ~` takes you to your home folder on
macOS. On PowerShell, `cd ~` works too.

## Read a file

To print the first lines of a text file:

<OsTabs>
  <Fragment slot="windows">
```text
PS> Get-Content cafe_central_sales.csv -TotalCount 5
```
  </Fragment>
  <Fragment slot="macos">
```text
$ head -n 5 cafe_central_sales.csv
```
  </Fragment>
</OsTabs>

Both print the header and the first four sales. On Windows, accents may look odd in
older terminals. This is the encoding issue from lesson 1.7.

2. Run `pwd` to see where you are.

4. Run `ls` and check that you see the three files from the zip.
5. Print the first five lines of the sales file with the command above.

## Common mistakes

- **Expecting a message on success.** Many commands print nothing when they work.
- **Typing the prompt symbol.** Type only what follows `PS>` or `$`.
- **Being in the wrong folder.** Check with `pwd` before running anything.
- **Copying commands you do not understand.** Ask what a command does, and whether it
  changes or deletes anything, before running it.
- **Spaces in folder names.** Put quotes around the name: `cd "my folder"`.
- **Pasting into a terminal blindly.** A pasted command can contain hidden extra lines.

## Ask your AI assistant

<PromptExample>
  <Fragment slot="lousy">
What does this command do?
  </Fragment>
  <Fragment slot="whatGoesWrong">
There is no command in the question. When you do paste one, a lousy request gets an
explanation that may skip the part that matters most: whether it changes or deletes
files.
  </Fragment>
  <Fragment slot="good">
I am a beginner on macOS and found this command online: `ls -la ~/Documents`. Explain
what each part does, in one line each. Say clearly whether the command only reads
information, or whether it can change or delete anything. Tell me what the output will
look like.
  </Fragment>
  <Fragment slot="whyItWorks">
The prompt supplies the **input** (the command), the **context** (beginner, macOS), and a
**constraint** that forces a safety statement. The **output format** is one line per part.
  </Fragment>
  <Fragment slot="check">
Check the safety statement. Commands containing `rm`, `del`, `>`, `sudo`, or `format`
can change things. When in doubt, do not run it on real data.
  </Fragment>
</PromptExample>
