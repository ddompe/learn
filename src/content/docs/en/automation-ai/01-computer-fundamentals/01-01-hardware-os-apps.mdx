## Why this matters

When something goes wrong on a computer, the first question is: where is the problem?
Is the machine too slow, is Windows or macOS misbehaving, or is the program itself at
fault? People who can answer that question solve problems faster and ask better
questions of an AI assistant.

<CaseStudy>
	When Lucía double-clicks `cafe_central_sales.csv`, three layers cooperate. The
	disk holds the file, the operating system finds it and decides which program
	opens it, and Excel shows the rows on screen. If the file does not open, the
	cause sits in one of those layers.
</CaseStudy>

## The three layers

<Mermaid
	diagram={`flowchart TB

/>

**Hardware** is the physical machine. Four parts matter for this course:

- The **processor** (CPU) carries out instructions, one tiny step at a time, very fast.
- **Memory** (RAM) is the short-term workspace. It is fast, but it is emptied when the
  power goes off.
- **Storage** (a disk, or SSD) is the long-term shelf. It is slower, but it keeps files
  when the power is off.
- The **screen, keyboard, and network card** connect the machine to you and to the world.

An **operating system** (OS) is the program that manages the hardware and shares it
between other programs. It keeps track of files, starts and stops programs, controls
who may do what, and talks to devices. Windows, macOS, and Linux are operating systems.

An **application** is a program that does a job for you, such as a spreadsheet, a
browser, or a code editor. Applications never touch the hardware directly. They ask the
operating system, for example, "please read this file".

A useful analogy: the hardware is a building, the operating system is the building
manager, and applications are the tenants. Tenants ask the manager for keys and
electricity. They do not rewire the building. Like every analogy, it has limits: a
tenant that misbehaves can still slow down the whole building.

## Memory versus storage

Many people confuse these two, and the confusion causes real losses.

When you open a spreadsheet, the OS copies the file from storage into memory. Your
changes live in memory until you save. If the power fails before you save, the changes
are gone. Saving writes memory back to storage.

## Hands-on

### Worked example: where is the problem?

Match each symptom with the layer most likely at fault.

| Symptom                                               | Likely layer                        |
| ----------------------------------------------------- | ----------------------------------- |
| Everything is slow when many programs are open        | Hardware (not enough memory)        |
| A file opens with the wrong program                   | Operating system (file association) |
| A formula works in one spreadsheet but not in another | Application                         |
| A message says "disk is full"                         | Hardware (storage)                  |

## Common mistakes

- **Mixing up memory and storage.** "My computer has 16 GB" can mean either. Always ask
  which one.
- **Blaming the application for everything.** Sometimes the cause is the OS or the disk.
- **Not saving.** Unsaved changes live only in memory.
- **Assuming a new computer fixes slow work.** If a program is badly designed, faster
  hardware helps only a little.

## Check yourself

<Checkpoint question="What is the difference between memory and storage?">
	Memory is fast and temporary, and is emptied when the power goes off. Storage
	is slower and keeps files permanently.
</Checkpoint>

<Checkpoint question="What does the operating system do?">
	It manages the hardware and shares it between programs: files, starting
	programs, devices, and permissions.
</Checkpoint>

<Checkpoint question="Why do applications ask the operating system to read a file instead of reading the disk directly?">
	The OS keeps files organised and protects them, so many programs can share the
	disk safely.
</Checkpoint>
