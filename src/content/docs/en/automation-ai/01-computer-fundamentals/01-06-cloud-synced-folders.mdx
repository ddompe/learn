## Why this matters

Many company laptops store Desktop and Documents inside OneDrive, Dropbox, or iCloud
without telling you. These folders behave like normal folders, but they are not. A
program that works in a local folder can fail in a synced one, and the error messages
rarely mention syncing.

<CaseStudy>
	Daniela keeps her Café Central files in `Documents`, which her company syncs
	to the cloud. After a script ran, some files changed back to older versions.
	The sync service had restored its own copies in the middle of the work.
</CaseStudy>

## How a synced folder works

A **cloud-synced folder** is a normal-looking folder watched by a background program.
When a file changes, the program uploads it. When the cloud copy changes, the program
downloads it. This is useful for backups and for sharing documents.

But the background program is another actor working on your files at the same time.

## Three ways it breaks projects

1. **Placeholders.** To save space, the sync program may keep only a small stand-in for a
   file. The real content is downloaded when you open it. A program that reads the
   folder may see an empty file or an error.
2. **Locks and conflicts.** The sync program may hold a file briefly while uploading it.
   If your program tries to write at that moment, it fails or creates copies named like
   `sales (conflicted copy).csv`.
3. **Too many small files.** Projects with thousands of small files, which you meet in
   Parts 3 and 4, make the sync program slow and sometimes confused.

Paths also change. A folder that you think of as `Documents` may actually live at a
longer path that includes the name of the sync service.

## Hands-on

### Worked example

Look at the path of your Documents folder, using the method from lesson 1.4. If the
path includes `OneDrive`, `Dropbox`, `iCloud`, or `Google Drive`, your Documents folder
is synced.

### Your turn

Pick a local folder for the course. Good choices are a new folder called `projects` in
your user folder, such as `C:\Users\<you>\projects` on Windows or `/Users/<you>/projects`
on macOS. Move the Café Central folder there, and check that the path does not
include the name of a sync service.

<Checkpoint question="Why is a short, simple location a good choice?">
	It is easy to type, has no spaces or accents, and no sync program is watching
	it.
</Checkpoint>

## Common mistakes

- **Not knowing the folder is synced.** Check the path.
- **Moving files into a synced folder while a script is using them.** Close programs first.
- **Disabling sync on a company laptop without asking.** Company policy may require it.
  Choose another folder instead.
- **Treating sync as version control.** Sync keeps the latest copy. Part 3 teaches real
  history.

## Check yourself

<Checkpoint question="Name one way a synced folder differs from a local one.">
	A background program uploads and downloads files, which can leave
	placeholders, lock files, or create conflicting copies.
</Checkpoint>

<Checkpoint question="How can you tell whether a folder is synced?">
	Look at its full path, which often includes the name of the sync service.
</Checkpoint>

<Checkpoint question="Is sync the same as version control?">
	No. Sync mirrors the latest state. Version control keeps a history you can
	return to.
</Checkpoint>
