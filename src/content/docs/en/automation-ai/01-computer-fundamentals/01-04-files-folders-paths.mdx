## Why this matters

Every program that reads a file needs to be told where the file is. That description is
a **path**. Most "file not found" errors come from a path that is slightly wrong. If you
can read paths, you can fix those errors in seconds.

<CaseStudy>
	In lesson 0.3 you unzipped the Café Central data into a folder. A script that
	wants to read `cafe_central_sales.csv` needs the path to that file. Without
	it, even a perfect script fails.
</CaseStudy>

## Files and folders

A **file** holds information under a name. A **folder** (also called a directory)
holds files and other folders. Folders inside folders form a tree.

<Mermaid
	diagram={`flowchart TD
  A["Documents"] --> B["cafe-central"]
  A --> C["taxes"]
  B --> D["cafe_central_sales.csv"]
  B --> E["cafe_central_customers.json"]`}
/>

A **path** lists the folders you pass through to reach a file, ending with its name.
For the sales file above, the steps are: Documents, then cafe-central, then the file.

## Absolute and relative paths

An **absolute path** starts from the very top of the disk. It works from anywhere. A
**relative path** starts from where you are now. It is shorter, but means different
things in different places.

| Kind     | Windows                                           | macOS                                           |
| -------- | ------------------------------------------------- | ----------------------------------------------- |
| Absolute | `C:\Users\Lucia\Documents\cafe-central\sales.csv` | `/Users/lucia/Documents/cafe-central/sales.csv` |
| Relative | `cafe-central\sales.csv` (from `Documents`)       | `cafe-central/sales.csv` (from `Documents`)     |

Notice three things:

- Windows uses a backslash `\` between folders and starts with a drive letter such as `C:`.
- macOS uses a forward slash `/` and starts with a single `/`, the top of the disk.
- The place you are "standing in" is called the **current folder** or working folder.
  Relative paths are measured from there.

Two shortcuts are useful. A single dot `.` means "this folder". Two dots `..` mean "the
folder above this one".

## Common mistakes

- **Confusing a folder's display name with its path.** Finder and Explorer show friendly
  names such as "Desktop". The real path is longer.
- **Using a relative path from the wrong place.** The same relative path points to
  different files depending on the current folder. If in doubt, use an absolute path.
- **Spaces and accents in names.** They are allowed, but some tools need quotes around
  the path. Prefer simple names such as `cafe-central`.
- **Copying a Windows path into a Mac script.** The separators and the drive letter will
  not work.
- **Editing the file name by hand.** A single typo makes the path wrong.

<Checkpoint question="Why does a Windows path not work on a Mac?">

	uses forward slashes.
