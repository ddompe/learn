## Why this matters

Every program that reads a file needs to be told where the file is. That description is
a **path**. Most "file not found" errors come from a path that is slightly wrong. If you
can read paths, you can fix those errors in seconds.

<CaseStudy>
	In lesson 0.3 you unzipped the Café Central data into a folder. A script that
	wants to read `cafe_central_sales.csv` needs the path to that file. Without
	it, even a perfect script fails.
</CaseStudy>

## The filesystem

Your computer stores information on a **disk**. The main one is inside the computer
(the internal disk). You can also plug in others: a USB stick, an external hard drive,
or a memory card. A disk on its own is just a very long row of storage space. Nothing
in it says "this part is the sales report".

The **filesystem** is the system that adds that order. It keeps a table of names and
records which part of the disk belongs to each one. It lets you group things into
folders, and it remembers details such as when a file was last changed. Every disk has
one, and the operating system (lesson 1.1) reads it for you. Different disks may use
different kinds of filesystem, which is why a drive from a Windows PC sometimes needs
help to work on a Mac. You do not need to know the kinds. You only need to know that
each disk arrives organized as folders and files.

You have used a filesystem for years, through a program that draws it for you: **File
Explorer** on Windows or **Finder** on macOS. When you double-click a folder, drag a
file into another, or plug in a USB stick and see it appear in the sidebar, you are
using the filesystem.

<Mermaid
	diagram={`flowchart LR
  A["You: File Explorer or Finder"] --> B["Operating system"]
  B --> C["Filesystem on the internal disk"]
  B --> D["Filesystem on a USB stick"]`}
/>

On Windows, each disk gets a letter (`C:` is usually the internal one, and a USB stick
might become `E:`). On macOS, all disks hang from one top folder, and an external disk
appears inside the folder `/Volumes`. Both systems end up with the same idea, which
comes next.

## Files and folders

A **file** holds information under a name. A **folder** (also called a directory)
holds files and other folders. Folders inside folders form a tree.

<Mermaid
	diagram={`flowchart TD
  A["Documents"] --> B["cafe-central"]
  A --> C["taxes"]
  B --> D["cafe_central_sales.csv"]
  B --> E["cafe_central_customers.json"]`}
/>

A **path** lists the folders you pass through to reach a file, ending with its name.
For the sales file above, the steps are: Documents, then cafe-central, then the file.

## Why automation needs paths as text

When you use File Explorer or Finder, you point and click. You see the tree, you open
folders with the mouse, and you recognize the file by its icon. A program has no mouse
and no eyes. It cannot "open the cafe-central folder". The only way to tell it which
file to use is with **text** that describes the way to the file. That text is the path.

This matters for automation in three ways.

- **A script needs it written down.** Reading `cafe_central_sales.csv` in a script
  means putting its path in the code, as a piece of text.
- **A path can be reused.** The same text works every month, with no clicking. That is
  what lets a task run without you.
- **A path can be changed by a program.** A script can build `sales_2026-03.csv` from
  a month name, or loop over every file in a folder. You cannot do that with a mouse.

So the habit to learn is this: when you look at a folder in Explorer or Finder, also
learn to read it as a line of text.

## Absolute and relative paths

An **absolute path** starts from the very top of the disk. It works from anywhere. A
**relative path** starts from where you are now. It is shorter, but means different
things in different places.

| Kind     | Windows                                             | macOS                                             |
| -------- | --------------------------------------------------- | ------------------------------------------------- |
| Absolute | `C:\Users\Daniela\Documents\cafe-central\sales.csv` | `/Users/daniela/Documents/cafe-central/sales.csv` |
| Relative | `cafe-central\sales.csv` (from `Documents`)         | `cafe-central/sales.csv` (from `Documents`)       |

Notice three things:

- Windows uses a backslash `\` between folders and starts with a drive letter such as `C:`.
- macOS uses a forward slash `/` and starts with a single `/`, the top of the disk.
- The place you are "standing in" is called the **current folder** or working folder.
  Relative paths are measured from there.

Two shortcuts are useful. A single dot `.` means "this folder". Two dots `..` mean "the
folder above this one".

## Common mistakes

- **Confusing a folder's display name with its path.** Finder and Explorer show friendly
  names such as "Desktop". The real path is longer.
- **Using a relative path from the wrong place.** The same relative path points to
  different files depending on the current folder. If in doubt, use an absolute path.
- **Spaces and accents in names.** They are allowed, but some tools need quotes around
  the path. Prefer simple names such as `cafe-central`.
- **Copying a Windows path into a Mac script.** The separators and the drive letter will
  not work.
- **Editing the file name by hand.** A single typo makes the path wrong.
