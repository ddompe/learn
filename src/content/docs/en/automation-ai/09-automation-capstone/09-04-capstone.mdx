## The requirements

Your pipeline is done when it meets every item. They are written so that you can check each one.

### Data

1. Reads the semicolon-separated, UTF-8 sales CSV from the `data` folder.
2. Parses all three date formats (slash dates are day first) and all three amount formats.
3. Removes exact duplicate rows, merges the category spelling variants, and keeps rows with no customer, marked.
4. Amounts are exact decimals. The cleaned January data has 240 rows and a grand total of 474,061.00 colones.

### Behaviour

1. Settings come from a config file; the month and output folder can be overridden on the command line.
2. Writes a log file and prints progress. A wrong or missing file stops the run with a clear message and exit code 2.
3. Writes the category totals as CSV and as a formatted Excel file.
4. Produces the report, with a captioned weekly chart that starts at zero, a category table, and numbers in the text that come from the data, in HTML, Word, and PDF.
5. The report can be rendered for a single category with a parameter.

### Quality

1. Tests cover the parsers, the cleaning (including the 240-row result), and each failure.
2. A README says what it does, how to run it, and which decisions were made.
3. The project is in Git with clear commits, in a private repository, with no secrets or private data.
4. It runs on a schedule, on your computer or in GitHub Actions, and you have seen it run at least once from the schedule.

## How to build it with an assistant

The method that works is the same at each step: **small step, clear prompt, run, check, commit.**

| Step | Build                                             | Check before you commit                                    |
| ---- | ------------------------------------------------- | ---------------------------------------------------------- |
| 1    | Project with uv; README skeleton; `.gitignore`    | `uv run python --version`; first commit                    |
| 2    | Parsers: `parse_amount`, `parse_date`, `simplify` | Tests with hand-worked values pass                         |
| 3    | `clean_sales` with a log                          | 246 rows in, 240 out, counts in the log match              |
| 4    | Totals; grand total check                         | 474,061.00; a manual total for one category                |
| 5    | Config file, CLI options, logging, exit codes     | Trigger the missing-file and wrong-month failures          |
| 6    | CSV and Excel outputs                             | Open the Excel file; accents and number format look right  |
| 7    | The Quarto report; parameter; three formats       | Totals in the text equal the table; axis starts at zero    |
| 8    | Tests for the pipeline, README finished           | `uv run pytest` is green; a stranger can follow the README |
| 9    | Push to a private repository                      | No secrets; `.env` ignored                                 |
| 10   | Schedule it                                       | Run it two minutes ahead, then at the real time            |

You have already written most of the code for steps 2 to 7 earlier in the course. You can
reuse it, adapt it, or rebuild it with the assistant. If you rebuild it, compare what you
get with your earlier version: it is a good way to find an assistant's mistake.

### Working rules

1. **One step per prompt.** Never ask for the whole pipeline at once.
2. **Give the assistant the facts:** file layout, formats, and the exact rules.
3. **Write or check the test first** when you can: work out the expected answer by hand.
4. **Read every line** before you accept it (lesson 3.3).
5. **Commit after each step** that works, with a clear message (lesson 3.5).
6. **When it breaks,** give the assistant the full traceback and the code (lesson 3.10).
7. **No private data in prompts** (lesson 2.8). The course data is fictional.

## Common mistakes

- **Asking for everything at once.** It produces a large, untested, wrong result.
- **Skipping the checks** because the assistant sounded sure (lesson 2.6).
- **Committing data or keys.**
- **Scheduling before it works by hand.**
- **Changing the data to make the test pass.**
- **No README.** In six months the project is a mystery.
- **Never watching the first scheduled run.**
