## Why this matters

The point of a report with code is that the numbers in the text, the chart, and the table
all come from the data, in one place. Nobody types a figure. Change the data, rerun, and
the whole report updates, and the text still agrees with the table.

## The report

<Example file="part08/monthly_report.qmd" />

Walk through it.

### The header

The header sets the title and the date. `execute: echo: false` hides the code, so readers
see results, and `warning: false` hides warning messages. `jupyter: python3` says which
engine runs the code. The `format` section lists three outputs (lesson 8.5).

### Code chunks

A chunk starts with three backticks and `{python}`, and ends with three backticks.
Lines that start with `#|` are **chunk options**. For example:

| Option                   | Effect                                    |
| ------------------------ | ----------------------------------------- |
| `#\| echo: true`         | Show this chunk's code                    |
| `#\| label: fig-weekly`  | Name the figure so text can refer to it   |
| `#\| fig-cap: "..."`     | Caption for the figure                    |
| `#\| tags: [parameters]` | Mark the chunk as parameters (lesson 8.4) |

All the chunks share the same memory, in order from the top, like a notebook (lesson 4.5).
They run once when the document renders.

### Numbers inside sentences

`{python} count` written between single backticks inside a sentence is **inline code**.
Quarto runs it and writes the result into the sentence, so "55 sales for a total of
112,614 colones" can never disagree with the data. The report formats numbers with an
f-string: `f"{total:,.0f}"` adds thousands separators.

### Figures, tables, and cross references

The weekly chart is a normal matplotlib chart (lesson 7.2). Because the chunk has a label
starting with `fig-` and a caption, Quarto numbers it, and the text can write `@fig-weekly` to say
"Figure 1".

The table is made as Markdown text, as in lesson 5.6, and shown with `Markdown(...)`.
That works in HTML, Word, and PDF alike, with no extra packages.

## Test the code without rendering

Rendering takes a few seconds, and an error in the middle of a chunk can be hard to see.
It is useful to check that the code runs by itself. The example project includes a small
helper that runs the report's Python chunks as a plain Python script, so that the tests (lesson 3.9)
can check the numbers. If the code fails, you see an ordinary traceback (lesson 3.10).

## Common mistakes

- **Leaving the code visible in a management report.** Set `echo: false`.
- **Pasting numbers into the text.** Use inline code.
- **Paths that depend on where you render.** Quarto runs the code from the document's folder, so relative paths are measured from there.
- **A chunk that fails halfway.** Run the code on its own first.
- **Warnings in the output.** Fix the cause, or hide them knowingly.
- **A stale cache after installing a package.** If Quarto still reports a missing package after you installed it, delete the hidden `.quarto` folder in your project and render again.
