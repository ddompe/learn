## Why this matters

Daniela's boss does not want one report. The juice supplier wants the juice numbers, the
bakery wants the cake numbers, and so on. Copying the report five times means five
files to fix whenever something changes. A **parameterised report** has one source and a
few inputs, and produces as many versions as you need.

<CaseStudy>
	Café Central wants one report per category, each with its own totals and
	chart, all from the same `monthly_report.qmd`.
</CaseStudy>

## Parameters

Mark one chunk as holding the parameters, with default values:

```text
#| tags: [parameters]
category = "all"
```

That is the first chunk of the report in lesson 8.3. The later chunks read `category`, and filter the
data if it is not `"all"`. The defaults make the report work with no parameters at all.

## Set a parameter from the command line

```text
uv run quarto render monthly_report.qmd --to html -P category:jugo --output report-jugo.html
```

- `-P category:jugo` sets the parameter, written as `name:value`.
- `--output` chooses the file name. Without it, each render would overwrite
  `monthly_report.html`.
- You can repeat `-P` for several parameters.

Parameters need the **papermill** package in your project: `uv add papermill`. If it is
missing, Quarto stops with the message "The papermill package is required for processing
--execute-params".

## Render all of them

A short script builds the commands for every category and prints them. With `--run`, it runs them.

<Example file="part08/render_reports.py" />

Read the script first and run it without `--run`. It prints five commands, one per category,
like the one above. Reading the plan before executing it is a good habit for any
automation. Then:

```text
uv run python render_reports.py --run
```

This writes `report-cafe.html`, `report-jugo.html`, and so on. Part 9 shows how to run a
script like this on a schedule.

The same idea works for months: a `month` parameter and a loop over the months you need.

## Common mistakes

- **Forgetting the `parameters` tag.** The command-line value is ignored or an error appears.
- **Missing `papermill`.**
- **Stale `.quarto` cache** after installing it. Delete that folder and render again.
- **Same `--output` for every render.** Each overwrites the previous.
- **Parameters of the wrong type.** `-P` values arrive as numbers or text. Convert deliberately.
- **Defaults that hide errors.** Test with a parameter and without.
