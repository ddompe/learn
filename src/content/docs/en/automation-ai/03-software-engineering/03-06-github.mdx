## Why this matters

So far, your history lives on one computer. **GitHub** is a website that hosts Git
repositories. A copy there gives you a backup, a way to work from another computer, and a
way to work with other people. It is also where most open source software lives.

Git and GitHub are different things. Git is the tool that tracks history. GitHub is a
service that stores repositories.

## Local and remote

A **remote** is a copy of the repository somewhere else, here on GitHub. You send commits
to it with **push** and fetch new commits from it with **pull**.

## Create a private repository

1. Sign in to [https://github.com](https://github.com) (the account from lesson 3.3).
2. Create a **new repository**. Give it a simple name, such as `cafe-central`.
3. Choose **Private**. Only you (and people you invite) can see a private repository.
4. Do not tick the options to add a README, license, or `.gitignore` for now.

**Warning:** a public repository is visible to everyone, and search engines index it. Do
not publish customer data or secrets. When in doubt, choose Private.

## Push from VS Code

In the Source Control view, choose **Publish Branch** (or **Publish to GitHub**). VS Code
asks you to sign in to GitHub in the browser, and then to choose a name and whether the
repository is private or public. Choose private. Your commits appear on github.com.

Or from the terminal, using the address that GitHub shows on the new repository page:

```text
git branch -M main
git remote add origin https://github.com/YOUR-NAME/cafe-central.git
git push -u origin main
```

From then on, `git push` sends new commits and `git pull` fetches changes made
elsewhere.

## Branches and pull requests

A **branch** is a separate line of work in the same repository. You can try a change on a
branch without touching the main line. A **pull request** is a request on GitHub to
merge a branch into the main line, so that others can review it first.

Solo, you often commit straight to `main`. In teams, a pull request is how changes get
reviewed. You do not need them now, but you will see the words everywhere.

## Common mistakes

- **Creating a public repository by accident.** Check the visibility before you click
  create. You can change it later, but anything that was public may have been copied.
- **Pushing secrets or personal data.** Deleting them later does not remove them from
  history (lesson 3.7).
- **Confusing Git and GitHub.** One is the tool, the other the hosting service.
- **Pasting a password for push.** Use the browser sign-in that VS Code offers.
- **Forgetting to push.** Commits stay on your computer until you push.
