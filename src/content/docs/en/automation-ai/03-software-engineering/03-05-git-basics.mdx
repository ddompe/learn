## Why this matters

Git only helps if you use it. This lesson takes you through the whole basic loop on a
real folder: tell Git about a project, change something, record the change, and look back.
It is also your safety net for the Copilot work in lesson 3.3.

## Install Git

VS Code uses Git, but does not include it.

<OsTabs>
	<Fragment slot="windows">
		Download **Git for Windows** from
		[https://git-scm.com](https://git-scm.com), run the installer, and accept
		the defaults. Then open a new terminal and run `git --version`.
	</Fragment>
	<Fragment slot="macos">
		Open Terminal and run `git --version`. If Git is missing, macOS offers to
		install the command line developer tools. Accept, wait for the installation,
		and run the command again.
	</Fragment>
</OsTabs>

You should see a version number. Remember lesson 1.10: if the terminal says "not found",
open a new terminal window after installing.

Next, tell Git who you are. It writes this name on every snapshot. Use your name and an
email address you are happy to have in the history.

```text
git config --global user.name "Daniela Mora"
git config --global user.email "daniela@example.com"
```

## Three places

Git thinks in three places.

<Mermaid
	diagram={`flowchart LR
  A["Working folder: your files as they are now"] -->|"stage"| B["Staging area: the changes to record"]
  B -->|"commit"| C["History: saved snapshots"]`}
/>

- The **working folder** holds your files, as you edit them.
- The **staging area** holds the changes you chose for the next snapshot. You pick what
  goes in, so each snapshot tells one clear story.
- A **commit** is a snapshot saved in the history, with a **commit message**.

## The loop in VS Code

1. Open the folder in VS Code (lesson 3.2).
2. Click the **Source Control** icon in the left bar, and choose **Initialize Repository**.
3. The files appear in a list of changes. Hover over a file and click the **+** to stage
   it, or stage all.
4. Type a message in the box, such as `Add the January sales data`, and click **Commit**.
5. Edit a file, and the change appears in the list again. Stage it and commit again.
6. Click on a changed file to see the **diff**, which shows removed lines in red and
   added ones in green.

## The same loop in the terminal

```text
git init
git status
git add cafe_central_sales.csv
git commit -m "Add the January sales data"
git log --oneline
```

- `git init` makes the folder a repository.
- `git status` shows what changed and what is staged.
- `git add` stages a file.
- `git commit -m` saves the snapshot with a message.
- `git log --oneline` lists the history, one line per commit.

VS Code and the terminal are two views of the same thing. You can mix them.

## Good commit messages

A message should say what and why, in a short line that completes "This commit will...":

- Good: `Fix duplicate rows in January totals`
- Poor: `update`, `stuff`, `final`

## Hands-on

### Worked example

1. In VS Code, open the Café Central folder.
2. Initialise the repository and make a first commit that contains the data files.
3. Create a file `notes.md` that says "Dates come in three formats." Stage it and commit

4. Open the history with `git log --oneline` in the terminal and find both commits.

## Common mistakes

- **Not installing Git.** Source Control shows a message about Git missing.
- **Committing everything under the message "update".** Future you will not know what is
  in it. Write the reason.
- **Committing secrets or private data.** Check what you stage (lesson 3.7).
- **Making one giant commit at the end.** Small commits are easier to understand and undo.
- **Panicking over a command you do not understand.** Run `git status` first. It changes nothing.
