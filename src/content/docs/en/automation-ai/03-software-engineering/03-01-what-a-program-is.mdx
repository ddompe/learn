## Why this matters

Everything you will automate is a **program**: a list of instructions that a computer
follows exactly. If you can read a short program, you can check what an AI assistant
wrote for you. You do not need to write programs yet. Reading comes first.

<CaseStudy>
	Daniela's monthly routine, in her head, is a list of steps: open the file,
	count the rows, check the total. A program is the same list written so
	precisely that a computer can follow it.
</CaseStudy>

## Source code

**Source code** is a program written as text in a **programming language**. It is saved
in a plain text file, like a CSV, but with different rules. Python is the language
this course uses. A Python file ends in `.py`.

A computer's processor cannot read Python directly. It only understands very low-level
instructions. Something has to translate.

## Interpreters and compilers

Two kinds of translators exist.

- A **compiler** translates the whole program ahead of time into a file the processor
  can run directly. You then run that file. Languages such as C and Rust work this way.
- An **interpreter** reads the source code and carries out the instructions as it goes,
  line by line. Python works this way.

<Mermaid
	diagram={`flowchart LR
  A["Source code: report.py"] --> B["Python interpreter"]
  B --> C["The computer does the work"]
  C --> D["Result on screen or in a file"]`}
/>

With Python you keep the source file and give it to the interpreter each time. That is
why you can read, change, and rerun a program quickly. It is also why you need Python
installed to run someone else's Python program (lesson 4.2).

## Reading a first program

<Example file="part03/01_program.py" />

Read it from top to bottom:

1. A line starting with `"""` is a **docstring**, a note that describes the program.
2. `from pathlib import Path` borrows a tool for working with file paths (lesson 1.4).
3. `sales_file = ...` stores the location of the sales file under the name `sales_file`.
   A name that holds a value is a **variable**.
4. `lines = ...` reads the file and splits it into a list of lines.
5. `print(...)` shows a message. The program reports 246 rows: the 240 sales plus six
   repeated lines. It subtracts one for the header.

You do not need to remember the syntax. The point is that every line does one thing, and
you can say what.

## Common mistakes

- **Thinking you must memorise syntax.** Reading comes first. Assistants help with writing.
- **Confusing the program with its result.** The `.py` file holds instructions. The output appears when you run it.
- **Editing a program in Word.** Use a code editor (lesson 3.2). Word adds hidden formatting.
- **Treating errors as failure.** An error message is the computer telling you what it could not do.
