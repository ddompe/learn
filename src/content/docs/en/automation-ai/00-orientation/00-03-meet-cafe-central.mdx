## Why this matters

Learning with made-up toy examples is dull, and the lessons rarely transfer to real
work. Real data is messy. It has odd dates, repeated rows, and spelling that differs
from row to row.

This course uses one fictional company throughout, with deliberately messy data. You
will meet the same problems in your own files.

<CaseStudy>
	Café Central S.A. is a made-up coffee company based in San José, Costa Rica,
	with several shops. Each shop exports its sales as a file. Daniela, the
	operations analyst, collects them every month, fixes them by hand, and builds
	a report for the owner.
</CaseStudy>

## Hands-on

### Look at the file without Excel

Do not open the sales file by double-clicking it. Excel would try to be helpful. It can
change dates and amounts, and if you save, it overwrites the original. Keep the files
exactly as downloaded.

Open `cafe_central_sales.csv` in a plain text editor instead. On Windows, use Notepad.
On macOS, use TextEdit (choose **Format**, then **Make Plain Text**). A **CSV** file
(comma-separated values) is plain text in which each line is a row and a separator
splits the columns. You should see something like this at the top:

```text
ID;Fecha;Cliente;Monto;Categoría
T001;01/01/2024;C004;2200.00;jugo
T002;2024-01-01;C002;1500;pastel
```

### Your turn

Scroll through the file and find **two** things that would confuse Excel or a script.
Here are the kinds of things to look for:

- Dates written in more than one style.
- Amounts written in more than one style, for example with a `$` or a comma.
- The same category spelled in several ways.
- Two identical lines in a row.
- The separator: this file uses `;` instead of `,`.

<Checkpoint question="What did you find? Show some answers">
	The file contains all of these. For example, the dates `01/01/2024`,
	`2024-01-01`, and `2024/01/01` mean the same day. An amount appears as
	`$1500,50`, mixing a currency symbol with a decimal comma. The category for
	coffee appears as both `café` and `cafe`. The transaction `T050` appears twice
	in a row. You do not need to fix any of this now. Parts 5 and 6 teach how.
</Checkpoint>

## Common mistakes

- **Opening the CSV in Excel and saving.** Excel can reinterpret dates and numbers
  silently, and saving overwrites the original. If you want to experiment, copy the file.
- **Losing the folder.** If you cannot find the data in a week, put it in `Documents` and
  write the location in a note.
- **Assuming the data is clean.** Messy data is normal. Noticing the mess is the first
  skill.
- **Storing the zip in a synced folder.** Cloud-synced folders can change files or hide
  them. Use a local folder for now.

## Ask your AI assistant

<PromptExample>
	<Fragment slot="lousy">Explain this CSV.</Fragment>
	<Fragment slot="whatGoesWrong">
		The assistant guesses the separator and the date format. It may read
		`$1500,50` as one thousand five hundred and fifty, or as 150,050, and it
		sounds confident either way.
	</Fragment>
	<Fragment slot="good">
		I am attaching the first 20 lines of a sales file for a coffee company.
		Columns: ID, Fecha, Cliente, Monto, Categoría. The separator is a semicolon.
		Tell me what each column probably means and list every assumption you make,
		especially about date formats and about how amounts are written. Then list
		any rows that look inconsistent.
	</Fragment>
	<Fragment slot="whyItWorks">
		The prompt gives **input** (an excerpt) and a **task** (describe each
		column). It requires the assistant to **list assumptions**, which turns
		hidden guesses into statements you can check. It also gives **context**:
		what kind of company and file this is.
	</Fragment>
	<Fragment slot="check">
		Pick three rows and check them by hand against the assistant's claims. Does
		the date mean what it says? Is the amount what you see in the file? Do not
		trust a summary of a file until you have checked a few rows yourself.
	</Fragment>
</PromptExample>
