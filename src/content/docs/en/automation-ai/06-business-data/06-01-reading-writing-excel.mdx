## Why this matters

Most business data starts life in Excel, and not in tidy form. Workbooks have titles, merged
header cells, subtotal rows, and several sheets. Reading one with default settings
gives you columns named `Unnamed: 1`. To automate a report, you have to turn the
workbook people made into a table a program can use.

## Two tools

- **pandas** reads a sheet into a table (a DataFrame, lesson 6.2) with `pd.read_excel`.
- **openpyxl** is the library underneath. It gives access to details such as merged
  ranges, fonts, and formulas. pandas uses it automatically for `.xlsx`, and you
  already have it in the project.

Both are installed in the course project (lesson 4.13). If you start your own project, add them with `uv add pandas openpyxl`.

## Reading a sheet

<Example file="part06/01_excel.py" />

Step by step:

1. `sheet_name=None` reads **all** sheets into a dictionary. The workbook has two: `Resumen`
   and `Notas`.
2. Reading `Resumen` with the defaults treats the first row, the merged title, as the header.
   Every other column becomes `Unnamed: n`. Nothing is wrong with the file. The default is wrong for this layout.
3. Reading with `header=None` gives the raw grid. Row 1 holds the month names, but a
   merged cell stores its value only in its **first** cell. The other cell is empty.
   `ffill()` ("forward fill") copies the month across.
4. We join the month and the label to make clear column names, such as `Enero 2024 Monto`,
   and keep the rows below the headers.

## Things to check in a workbook

- **Several sheets.** Which one has the data?
- **Header rows.** How many, and merged?
- **Totals and notes in the data area.** Remove them before analysis.
- **Formulas.** pandas reads the last saved result. A file written by a program
  may have formulas without saved results, which read as empty.
- **Hidden rows, columns, and sheets.**

## Writing Excel

`DataFrame.to_excel(path, index=False)` writes a sheet. Lesson 6.10 covers formatting.
Writing creates a new file, and does not edit your original.

## Common mistakes

- **Trusting the default header.** Look at the raw grid first.
- **Forgetting that merged cells only keep their first value.**
- **Reading all sheets and assuming they match.**
- **Leaving totals rows in the data.**
- **Overwriting the original workbook.** Write results to a new file.

## Check yourself

<Checkpoint question="Why do merged headers produce `Unnamed` columns?">
	The default treats the first row as the header, and a merged cell fills only
	its first column, leaving the others unnamed.
</Checkpoint>

<Checkpoint question="What does sheet_name=None do?">
	It reads all sheets into a dictionary.
</Checkpoint>

<Checkpoint question="What does ffill do here?">
	It copies the last non-empty value forward, so the month name fills the merged
	range.
</Checkpoint>
