## Why this matters

**SQL** (Structured Query Language) is the standard language for asking questions of tables.
Databases, data warehouses, and analytics tools all speak it. Learning a little SQL lets you
talk to them, and gives you a second way to check your pandas results. **DuckDB** is a small
database that runs inside your Python program, so there is nothing to install or run. It
queries DataFrames, CSV files, and Parquet files directly.

## The shape of a query

A query says what you want, not how to compute it.

```text
SELECT categoria, count(*) AS ventas, round(sum(monto), 2) AS total
FROM sales
GROUP BY categoria
ORDER BY total DESC
```

| Clause     | Meaning                       | pandas equivalent     |
| ---------- | ----------------------------- | --------------------- |
| `SELECT`   | Which columns or calculations | Choose columns, `agg` |
| `FROM`     | Which table                   | The DataFrame         |
| `WHERE`    | Keep only matching rows       | Boolean filter        |
| `GROUP BY` | One row per group             | `groupby`             |
| `ORDER BY` | Sort the result               | `sort_values`         |

## When to pick SQL or pandas

Use pandas to clean and reshape in Python. Use SQL when the data sits in a database, when
the question is a plain summary, or when colleagues already read SQL. Many analysts mix both.

## Common mistakes

- **Double quotes around text values.** In SQL they mean column names. Use single quotes.
- **Forgetting `GROUP BY`** when mixing a column and a sum.
- **Querying uncleaned data.** Clean first, or the groups are wrong.
- **Trusting generated SQL without running a check.**
- **Assuming all databases share every function.** Dialects differ a little.
