## Why this matters

You cannot hand an assistant a PDF or a workbook and be sure it understands the layout.
Converting a document to Markdown first gives you plain text that you can read, fix,
and send. The conversion is never perfect, so you need to know where it goes wrong and
how to check.

<CaseStudy>
	Daniela wants an assistant to answer questions about the supplier invoice and
	the monthly summary. She converts both to Markdown and reviews the result
	before sending it.
</CaseStudy>

## What conversion does

A converter reads the structure that a file has, and writes the closest Markdown. For a
Word file, that structure is explicit (headings, lists, tables), so conversion is
usually good. For a PDF, the structure is missing, so the tool must guess from positions.

## See it by hand

Two lessons from this small experiment.

1. **Merged cells lose meaning.** The workbook's month headers (`Diciembre 2023`,
   `Enero 2024`) sit in merged cells above `Ventas` and `Monto`. The converted table has
   two `Ventas` and two `Monto` columns with no month. A person can no longer tell
   which is which.
2. **PDF tables must be rebuilt.** By grouping words with the same `y` position, the
   script recovers each invoice row. This works on a clean, simple PDF. Real invoices
   have wrapped lines, columns of varying width, and footers, and break such simple rules.

## Tools

Several tools convert documents to Markdown. They differ in strengths and change fast.
Last verified on 2026-10-03.

- **pandoc** is a long-established command-line converter between many document formats.
  It is strong for Word and similar structured documents.
- **MarkItDown** is an open source Python tool that converts Office files, PDFs, and
  other files to Markdown for use with language models.
- **Docling** is an open source toolkit that analyses document layout, and handles
  tables and scanned pages more ambitiously.

Check each project's page for what it supports today: [pandoc](https://pandoc.org),
[MarkItDown](https://github.com/microsoft/markitdown), and
[Docling](https://github.com/docling-project/docling). Follow lesson 3.8's habits before installing: check the name,
the maintainers, and the release history.

## A quality checklist

Whatever the tool, compare the output with the original:

1. **Count** the rows, columns, and sections.
2. **Check numbers** in three places: first, middle, last.
3. **Check headings** and their levels.
4. **Look for lost content:** footnotes, headers, merged cells, text in images.
5. **Look for scrambled order,** especially in multi-column pages.
6. **Check special characters:** accents and currency signs.

## Common mistakes

- **Trusting the output without a check.**
- **Using one tool for everything.** Try another when a document converts badly.
- **Converting scanned pages without OCR.** You get nothing.
- **Sending confidential documents to an online converter.** Lesson 2.8 applies.
- **Forgetting the original.** Keep it, and note the tool that you used.
