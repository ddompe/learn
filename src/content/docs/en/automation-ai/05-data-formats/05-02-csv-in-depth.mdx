## Why this matters

CSV looks too simple to go wrong, yet it causes more data problems than any other
format. There is no official standard that everyone follows. The delimiter, the
encoding, the quotes, and the way numbers and dates are written all vary. The Café Central
file has its own choices: `;` separators, UTF-8, mixed amounts. You must check them
instead of assuming.

	Then amounts like `$1500,50` break her totals. The file is not broken. It
	follows the Spanish-locale conventions.

## What a CSV is

A **CSV** (comma-separated values) file is a text file where each line is a row, and a
**delimiter** character separates the columns. The first line is often a header with
column names. That is the whole format, and everything else is a convention.

## The delimiter and the decimal comma

In English-speaking locales, numbers use a decimal point (`1500.50`), so the comma is free
to separate columns. In many Spanish-speaking and European locales, the decimal
separator is a comma (`1500,50`). A comma-delimited file would then be ambiguous, so the
spreadsheet program defaults to a **semicolon** as the list separator in those locales.
That is why a CSV saved from Excel in Spanish has `;`.

## Quoting

If a field contains the delimiter, a quote, or a newline, the writer wraps it in double
quotes, and doubles any quote inside it: `"dijo ""hola"""`. The `csv` module does this for
you. Never build CSV lines by joining text yourself.

## Encoding

A CSV is plain text, so it has an encoding (lesson 1.7). Three cases appear:

- **UTF-8** is the best default.
- **UTF-8 with BOM** starts with three invisible bytes. Excel uses them as a hint that the
  file is UTF-8. Some tools then show a stray character at the start of the first header.
- **Latin-1 or Windows-1252** appears in files from older systems.

If accents look wrong, the encoding is the first suspect. Tell the reading tool which one to use.

## Dates and numbers

CSV has no types. Everything is text until you convert it. The Café Central file mixes
`2024-01-01`, `01/01/2024`, and `2024/01/01` for dates, and `1500`, `1400.50`, and
`$1500,50` for amounts. Part 6 covers cleaning. For now: never trust a column's type
from its look.

## Common mistakes

- **Assuming the comma.** Look at the file first.
- **Splitting lines by hand.** Use the `csv` module so that quotes work.
- **Opening and saving in Excel.** It may change dates, drop zeros, and change the encoding.
- **Ignoring the BOM.** A stray character in the first header name is the sign.
- **Writing a CSV with the system's default encoding.** Pass `encoding="utf-8"`.
