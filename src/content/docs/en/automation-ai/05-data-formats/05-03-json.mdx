## Why this matters

When data has structure, such as a customer with several phone numbers, a flat table is
awkward. **JSON** (JavaScript Object Notation) handles nesting, and it is the standard way
for programs and web services to exchange data. You will meet it in APIs (lesson 1.12),
in settings, and in everything an AI service sends back.

<CaseStudy>
	Café Central's customer list is stored as JSON. Daniela finds that her tools
	refuse to read it, because someone added comment lines at the top.
</CaseStudy>

## The pieces

JSON has only a few building blocks.

| Piece   | Written as              | Example                     |
| ------- | ----------------------- | --------------------------- |
| Object  | `{ "key": value, ... }` | `{"id": "C001"}`            |
| Array   | `[ value, value ]`      | `["frecuente", "san josé"]` |
| String  | Double quotes           | `"Ana López"`               |
| Number  | Digits                  | `1500.5`                    |
| Boolean | `true` or `false`       | `true`                      |
| Null    | `null`                  | `null`                      |

Objects and arrays can contain each other, to any depth. In Python, an object becomes a
dictionary, an array becomes a list, and `null` becomes `None` (lessons 4.8 and 4.10).

<Mermaid

Rules that trip beginners: keys and strings must use **double** quotes, there is no
trailing comma after the last item, and there are **no comments**.

## Reading the customer file

<Example file="part05/03_json.py" />

The real file starts with two lines beginning `//`. Strict JSON does not allow comments,
so `json.loads` fails. The script removes the comment lines first, and then reads 8
customers. Some have an empty name or email, which the script reports. In the written
example, a missing email is `null`.

Notice `ensure_ascii=False` in the last two lines. Without it, `json.dumps` writes `é` as
`\u00e9`. Both are valid JSON, but the first is easier to read.

## Missing values

JSON can say "no value" in three ways, and files mix them: `null`, an empty string `""`,
or a missing key. Handle all of them. Test with `if not value` for empty and `None`, or
use `.get("email")` for a missing key.

## Common mistakes

- **Treating a file with comments as valid JSON.** Remove them first, or ask for a clean file.
- **Single quotes or trailing commas.** Both are invalid.
- **Assuming every key exists.** Use `.get()`.
- **Forgetting `ensure_ascii=False`** when writing accents for people to read.
- **Confusing `null`, empty, and missing.**
