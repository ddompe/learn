## Por qué importa

Los asistentes de IA, el almacenamiento en la nube y la mayoría de las herramientas de
negocio funcionan por internet. Cuando una falla, el error dice cosas como "404",
"timeout" o "403 Forbidden". Conocer la conversación básica que hay detrás de una página
web te permite leer estos mensajes en lugar de temerles. También te prepara para la
lección 1.12.

## Clientes y servidores

Un **cliente** pide algo. Un **servidor** responde. Tu navegador es un cliente. La
computadora que guarda una página web es un servidor. Un servidor es simplemente una
computadora que espera solicitudes. La mayoría están en centros de datos, pero una
laptop también puede ser un servidor.

## Anatomía de una URL

Una **URL** es la dirección de algo en la web.

<Example file="part01/11_urls.py" />

Cada parte responde una pregunta:

- El **esquema** (`https`) dice cómo conversar. HTTPS es la versión segura de HTTP.
- El **host** (`learn.dompe.space`) dice a qué computadora preguntarle.
- La **ruta** (`/en/automation-ai/`) dice qué quieres de ella.
- La **consulta** (`lang=en`) agrega detalles adicionales a la solicitud.
- El **fragmento** (`top`) es solo para tu navegador, para saltar a un punto de la página.

El host se convierte en una dirección numérica mediante el **DNS**, un servicio de
directorio para nombres.

## Solicitud y respuesta

La conversación usa un protocolo, o conjunto de reglas acordadas, llamado **HTTP**.

<Mermaid
	diagram={`sequenceDiagram
  participant B as Navegador (cliente)
  participant S as Servidor
  B->>S: Solicitud: GET /en/automation-ai/
  S-->>B: Respuesta: 200 OK más la página`}
/>

Una **solicitud** tiene un método (como GET para obtener, POST para enviar datos), una
ruta y encabezados con detalles adicionales. Una **respuesta** tiene un **código de
estado**, encabezados y normalmente un cuerpo, como la página o algunos datos.

Los códigos de estado se agrupan por su primer dígito:

| Código | Significado                               |
| ------ | ----------------------------------------- |
| 200    | OK, aquí está lo que pediste              |
| 301    | Se movió a otra dirección                 |
| 401    | Necesitas identificarte                   |
| 403    | Estás identificado pero no tienes permiso |
| 404    | No encontrado                             |
| 429    | Demasiadas solicitudes, ve más despacio   |
| 500    | El servidor tuvo un problema              |

## Manos a la obra

### Ejemplo resuelto

En tu navegador, abre `https://learn.dompe.space/en/` y lee su URL. Nombra su esquema,
host y ruta. Luego cambia el final de la dirección a `/en/no-such-page/` y presiona
Enter. ¿A qué código de estado corresponde esa situación?

### Ahora tú

Relaciona cada situación con un código de estado:

1. Escribiste la dirección de una página con un error de tipeo.
2. El servidor se cayó mientras respondía.
3. Iniciaste sesión, pero el archivo pertenece a otra persona.

<Checkpoint question="Muestra las respuestas">

1. 404, no encontrado.
2. 500, un problema del servidor.
3. 403, prohibido.

</Checkpoint>

## Errores comunes

- **Tratar un código de error como si fuera tu culpa.** Un código 5xx significa que el
  problema es del servidor, no tuyo.
- **Confundir 401 y 403.** 401 significa "¿quién eres?" y 403 significa "te conozco, pero no".
- **Usar HTTP para datos privados.** Usa siempre HTTPS.
- **Ignorar la consulta.** Todo lo que va después de `?` puede cambiar la respuesta.
- **Creer que una página se ve igual para todos.** Los servidores pueden responder distinto.
