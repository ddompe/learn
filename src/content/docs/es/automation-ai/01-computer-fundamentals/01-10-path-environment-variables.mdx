## Por qué importa

Escribes un comando y la computadora responde "comando no encontrado". El programa
está instalado, entonces ¿por qué el shell no lo ve? La respuesta casi siempre es PATH.
Es el error de principiante más común al instalar herramientas de desarrollo, y lo
volverás a encontrar en las Partes 3 y 4.

<CaseStudy>
	Daniela instala una herramienta para el proyecto de Café Central. En una
	terminal nueva escribe su nombre y recibe "no encontrado". La herramienta está
	en su disco. El shell simplemente no sabe dónde buscar.
</CaseStudy>

## Cómo encuentra el shell los programas

Cuando escribes un comando como `git`, el shell no busca en todo el disco. Sería lento.
En su lugar revisa una lista corta de carpetas, en orden, y ejecuta la primera
coincidencia. Esa lista se llama **PATH**.

<Mermaid
	diagram={`flowchart TD
  A["Escribes: git"] --> B["El shell lee PATH, una lista de carpetas"]
  B --> C{"¿Está git en la primera carpeta?"}
  C -- Sí --> D["Lo ejecuta"]
  C -- No --> E{"¿Hay otra carpeta?"}
  E -- Sí --> C
  E -- "Se acabó la lista" --> F["Error: comando no encontrado"]`}
/>

Así que "comando no encontrado" significa "no está en ninguna carpeta de PATH". La
solución es agregar la carpeta del programa a PATH, o usar la opción del instalador
que lo hace por ti.

## Variables de entorno

PATH es un ejemplo de **variable de entorno**: un fragmento de texto con nombre que el
sistema guarda para que los programas lo lean. Otras contienen tu nombre de usuario, tu
carpeta personal o configuraciones de una herramienta. Los programas las leen cuando
arrancan.

Las variables de entorno también son un lugar común para guardar secretos, como las
claves de API, fuera de tus archivos. La lección 1.12 y la Parte 3 vuelven sobre esto.

## Manos a la obra

### Ejemplo resuelto: leer una variable

<OsTabs>
  <Fragment slot="windows">
```text
PS> $env:USERNAME
PS> $env:PATH -split ';'
```
  </Fragment>
  <Fragment slot="macos">
```text
$ echo $USER
$ echo $PATH | tr ':' '\n'
```
  </Fragment>
</OsTabs>

El primer comando imprime tu nombre de usuario. El segundo imprime PATH, separado en una
carpeta por línea. El orden importa: el shell usa la primera coincidencia.

### Define una variable para esta sesión

<OsTabs>
  <Fragment slot="windows">
```text
PS> $env:CAFE_REPORT_NAME = "2024-01"
PS> $env:CAFE_REPORT_NAME
```
  </Fragment>
  <Fragment slot="macos">
```text
$ export CAFE_REPORT_NAME=2024-01
$ echo $CAFE_REPORT_NAME
```
  </Fragment>
</OsTabs>

Esta variable vive solo en la ventana de terminal actual. Cierra la ventana y desaparece.
Es una forma segura de experimentar. Hacer permanente una variable depende del sistema,
así que lo dejamos para cuando lo necesites.

### Ahora tú

1. Imprime tu PATH, una carpeta por línea.
2. Cuenta las carpetas.
3. Define una variable llamada `CAFE_REPORT_NAME`, imprímela, luego cierra la terminal,
   abre una nueva e imprímela otra vez. ¿Qué pasa?

<Checkpoint question="Muestra la respuesta del paso 3">
	La primera terminal imprime `2024-01`. La terminal nueva no imprime nada,
	porque la variable solo vivió en la primera sesión.
</Checkpoint>

## Errores comunes

- **Instalar una herramienta y usar la terminal anterior.** PATH se lee cuando arranca
  la terminal. Abre una ventana nueva después de instalar.
- **Editar PATH sin entenderlo.** Una edición equivocada puede ocultar otros programas.
  Prefiere instaladores que ofrezcan hacerlo.
- **Tener dos versiones de un programa.** Gana la que está antes en PATH, lo que puede confundir.
- **Escribir `$` o `$env:` en el shell equivocado.** La sintaxis difiere entre sistemas.
- **Poner secretos en archivos que compartes.** Guárdalos en variables de entorno o en
  archivos ignorados. Ver la Parte 3.
