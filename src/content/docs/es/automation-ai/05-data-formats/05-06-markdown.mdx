## Por qué importa

Este mismo curso está escrito en un pariente cercano de Markdown. También lo están las
respuestas que recibes de los asistentes de IA: los encabezados, las viñetas y las tablas
de una respuesta de chat son Markdown. Es el lenguaje común entre las personas y los
modelos de lenguaje. Conocerlo te permite escribir mejores prompts, leer la salida de la
IA como fue pensada y escribir documentos que las herramientas puedan procesar.

<CaseStudy>
	Daniela quiere pegar los totales por categoría en un asistente de IA y pedir
	comentarios. Una pequeña tabla en Markdown es más clara para el modelo que una
	captura de pantalla de una hoja de cálculo, y más económica que los mismos
	datos en JSON.
</CaseStudy>

## Lo esencial

**Markdown** es texto plano con unas pocas marcas ligeras que indican estructura.

| Escribes                                     | Obtienes                       |
| -------------------------------------------- | ------------------------------ |
| `# Título`                                   | Un encabezado principal        |
| `## Sección`                                 | Un encabezado de segundo nivel |
| `- elemento`                                 | Una viñeta                     |
| `1. paso`                                    | Un elemento numerado           |
| `**negrita**`, `*cursiva*`                   | Negrita y cursiva              |
| `[texto](https://…)`                         | Un enlace                      |
| `` `código` ``                               | Código en línea                |
| Un bloque delimitado por tres acentos graves | Un bloque de código            |
| Filas `\| a \| b \|`                         | Una tabla                      |

Como es solo texto, un archivo Markdown se abre en cualquier parte, se puede versionar en
Git y se ve razonable incluso sin renderizar.

## Por qué a los LLM les gusta Markdown

1. **Es texto plano,** así que son simplemente tokens (lección 2.1).
2. **Su estructura es ligera,** así que añade pocos tokens extra. Compara los tamaños al
   final de la salida: las mismas tres filas ocupan 130 caracteres en Markdown y 224 en
   JSON. Un CSV es el más corto (73), pero lleva menos estructura y tiene los problemas
   de delimitador de la lección 5.2.
3. **Los modelos han visto enormes cantidades,** en documentación, foros y
   repositorios de código. Lo escriben con fluidez.
4. **Es fácil de comprobar,** porque puedes leerlo sin renderizar.

Una regla práctica: para **personas y asistentes de chat**, usa Markdown. Para
**programas**, usa CSV o JSON. En ambos casos, no le envíes a un asistente una tabla muy
grande. Envía el encabezado y unas pocas filas (lección 2.3).

<Checkpoint question="Muestra la respuesta">

## Errores comunes

- **Olvidar la fila separadora** en una tabla. Sin ella, la tabla no se renderiza.
- **Barras verticales dentro de las celdas.** Escápalas como `\|`.
- **Enviar tablas enormes a un chat.** Envía una muestra.
- **Suponer que todas las herramientas renderizan Markdown igual.** Los detalles difieren.
- **Usar Markdown para datos que un programa debe analizar con exactitud.** Usa CSV o JSON.

## Compruébalo tú mismo

<Checkpoint question="¿Por qué los LLM manejan bien Markdown?">
	Es texto plano con estructura ligera, que los modelos han visto en enormes
	cantidades, y es fácil de leer sin renderizar.
</Checkpoint>

<Checkpoint question="¿Qué fila hace que una tabla Markdown se renderice?">
	La fila separadora bajo el encabezado, hecha de guiones.
</Checkpoint>

<Checkpoint question="¿Cuándo elegirías CSV en lugar de Markdown?">
	Cuando un programa leerá los datos, o cuando quieras el texto más compacto.
</Checkpoint>
