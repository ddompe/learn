## Por qué importa

El CSV es perfecto para tablas pequeñas y para intercambiar datos. Pero una tabla con
millones de filas se vuelve lenta de leer y grande de almacenar, y cada programa tiene
que volver a adivinar los tipos. **Parquet** es un formato binario hecho para analizar
tablas grandes. Lo encontrarás en cuanto trabajes con datos grandes o con herramientas
como DuckDB (lección 6.9).

<CaseStudy>
	El archivo de ventas de Café Central tiene 246 filas. El archivo del próximo
	año para todas las tiendas podría tener cientos de miles. Daniela quiere saber
	si el CSV seguirá funcionando.
</CaseStudy>

## Filas y columnas

Un CSV guarda los datos **fila por fila**: todos los campos de la primera venta, luego
los de la segunda. Parquet guarda **columna por columna**: todos los ID juntos, luego
todos los montos.

<Mermaid
	diagram={`flowchart LR
  A["CSV: fila 1, fila 2, fila 3"] --> B["Para leer una columna debes leer todo"]
  C["Parquet: columna ID, columna Monto, columna Fecha"] --> D["Lee solo las columnas que necesitas"]`}
/>

Beneficios del diseño columnar:

- **Lecturas más rápidas de pocas columnas.** Un análisis de montos no toca los nombres.
- **Archivos más pequeños.** Los valores de una columna se parecen, así que se comprimen bien.
- **Los tipos se guardan.** Las fechas y los números no se vuelven a adivinar.

<Example file="part05/09_parquet.py" />

El ejemplo repite los datos de ventas para crear una tabla más grande y luego la escribe
de ambas formas. El archivo Parquet es más pequeño. Después lee solo dos de las cinco
columnas. Las últimas líneas muestran un punto honesto: Parquet conserva los tipos que le
das. La columna `Monto` aquí sigue siendo texto, porque el CSV estaba desordenado. Primero
va la limpieza (Parte 6).

## Cuándo usarlo

| Situación                                     | Usa     |
| --------------------------------------------- | ------- |
| Tabla pequeña, o compartir con cualquiera     | CSV     |
| Una persona necesita abrirla y leerla         | CSV     |
| Tabla grande, analizada repetidamente         | Parquet |
| Quieres que los tipos sobrevivan entre pasos  | Parquet |
| Necesitas ver los datos en un editor de texto | CSV     |

Un patrón común: recibir un CSV desordenado, limpiarlo una vez, guardar la versión limpia
como Parquet y usarla para los análisis posteriores.

`Fecha` y `Monto`. ¿Qué formato encaja mejor y por qué?

<Checkpoint question="Muestra la respuesta">
	Parquet. Leer dos columnas se salta el resto, el archivo es más pequeño y las
	fechas y los montos conservan sus tipos.
</Checkpoint>

## Errores comunes

- **Usar Parquet para una tabla de 50 filas.** El CSV es más simple.
- **Escribir Parquet a partir de datos desordenados.** Límpialos primero.
- **Esperar abrirlo en un editor de texto.** Es binario.
- **Enviar Parquet a alguien sin las herramientas.** Comprueba antes.
- **Olvidar la dependencia extra.** pandas necesita un motor de Parquet, como pyarrow.
