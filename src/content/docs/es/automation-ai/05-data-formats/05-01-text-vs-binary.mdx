## Por qué importa

Los datos llegan en muchos formatos, y cada uno te exige algo distinto. Antes de abrir un
archivo, debes saber de qué tipo es: ¿puedes leerlo a simple vista, comparar dos
versiones, dárselo a un asistente de IA o ponerlo bajo Git? La respuesta depende de una
sola división: texto o binario.

<CaseStudy>
	Daniela recibe las ventas de Café Central como CSV, la lista de clientes como
	JSON, un resumen mensual como libro de Excel y una factura de proveedor como
	PDF. Cuatro archivos y cuatro maneras muy distintas de trabajar con ellos.
</CaseStudy>

## Texto y binario

La lección 1.5 presentó la idea. Un **formato de texto** guarda caracteres, así que un
editor de texto puede mostrarlo. CSV, JSON, YAML, TOML y Markdown son formatos de texto.
Un **formato binario** guarda bytes que solo el programa adecuado puede interpretar. El
`.xlsx` de Excel, el `.docx` de Word, el PDF y Parquet son binarios.

## Lo que te da el texto

1. **Puedes leerlo.** Ábrelo en cualquier editor y verás lo que contiene.
2. **Puedes comparar versiones.** Un cambio aparece como las líneas exactas que cambiaron.
3. **Git funciona bien.** El historial y la revisión tienen sentido (lección 3.4).
4. **Casi cualquier herramienta lo lee.** Python, Excel, bases de datos y asistentes de IA.
5. **Es robusto.** Si una parte de un archivo de texto se daña, el resto suele seguir legible.

<Example file="part05/01_text_vs_binary.py" />

La primera parte muestra el beneficio. Cambiar un monto cambia exactamente una línea, y
la diferencia se ve de un vistazo. La segunda parte muestra el costo: el archivo de Excel
empieza con `PK` (un zip, lección 1.5) y no se puede decodificar como texto.

## Lo que te da el binario

Los formatos binarios no son malos. Pueden ser **más pequeños**, **más rápidos** y llevar
**contenido más rico**: formato, gráficos y tipos. Excel conserva fórmulas y colores.
Parquet (lección 5.9) guarda tablas grandes de forma compacta. La contrapartida es que
necesitas un programa, o una biblioteca, para abrirlos.

## Elegir un formato

Pregunta para qué sirve el archivo.

| Si el archivo es...                              | Prefiere    |
| ------------------------------------------------ | ----------- |
| Una tabla para intercambiar entre herramientas   | CSV         |
| Registros anidados, o datos para un programa     | JSON        |
| Configuración que edita una persona              | YAML o TOML |
| Texto para que lean personas e IA                | Markdown    |
| Un informe para que las personas lean e impriman | PDF o Word  |
| Una tabla muy grande para análisis               | Parquet     |

## Errores comunes

- **Guardar los datos por defecto en un formato binario "bonito".** Pregunta quién lo usará y cómo.
- **Suponer que texto significa simple.** Los formatos de texto también tienen reglas y trampas.
- **Poner archivos binarios grandes en Git.** El historial crece y los cambios son opacos.
- **Abrir un archivo binario en un editor de texto y guardarlo.** Destruye el archivo.
- **Elegir un formato porque es familiar.** Elígelo porque se ajusta al uso.
