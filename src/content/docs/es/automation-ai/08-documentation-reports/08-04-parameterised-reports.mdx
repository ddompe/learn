## Por qué importa

El jefe de Daniela no quiere un solo informe. El proveedor de jugos quiere las cifras de
jugos, la pastelería quiere las de pasteles, y así sucesivamente. Copiar el informe cinco
veces significa cinco archivos que corregir cada vez que algo cambia. Un **informe
parametrizado** tiene una sola fuente y unas pocas entradas, y produce tantas versiones
como necesites.

<CaseStudy>
	Café Central quiere un informe por categoría, cada uno con sus propios totales
	y su gráfico, todos a partir del mismo `monthly_report.qmd`.
</CaseStudy>

## Parámetros

Marca un bloque como el que contiene los parámetros, con valores por defecto:

```text
#| tags: [parameters]
category = "all"
```

Ese es el primer bloque del informe de la lección 8.3. Los bloques posteriores leen
`category` y filtran los datos si no es `"all"`. Los valores por defecto hacen que el
informe funcione sin ningún parámetro.

## Define un parámetro desde la línea de comandos

```text
uv run quarto render monthly_report.qmd --to html -P category:jugo --output report-jugo.html
```

- `-P category:jugo` define el parámetro, escrito como `nombre:valor`.
- `--output` elige el nombre del archivo. Sin él, cada generación sobrescribiría
  `monthly_report.html`.
- Puedes repetir `-P` para varios parámetros.

Los parámetros necesitan el paquete **papermill** en tu proyecto: `uv add papermill`. Si
falta, Quarto se detiene con el mensaje "The papermill package is required for processing
--execute-params".

## Genéralos todos

Un script corto construye los comandos de cada categoría y los imprime. Con `--run`, los
ejecuta.

<Example file="part08/render_reports.py" />

Lee primero el script y ejecútalo sin `--run`. Imprime cinco comandos, uno por categoría,
como el de arriba. Leer el plan antes de ejecutarlo es un buen hábito para cualquier
automatización. Después:

```text
uv run python render_reports.py --run
```

Esto escribe `report-cafe.html`, `report-jugo.html`, y así sucesivamente. La Parte 9
muestra cómo ejecutar un script como este de forma programada.

La misma idea funciona para los meses: un parámetro `month` y un bucle sobre los meses
que necesites.

<Checkpoint question="Muestra la respuesta">

</Checkpoint>

## Errores comunes

- **Olvidar la etiqueta `parameters`.** El valor de la línea de comandos se ignora o
  aparece un error.
- **Falta `papermill`.**
- **Caché `.quarto` desactualizada** después de instalarlo. Elimina esa carpeta y vuelve
  a generar.
- **El mismo `--output` en cada generación.** Cada una sobrescribe la anterior.
- **Parámetros del tipo equivocado.** Los valores de `-P` llegan como números o texto.
  Conviértelos a propósito.
- **Valores por defecto que ocultan errores.** Prueba con un parámetro y sin él.

## Compruébalo tú mismo

<Checkpoint question="¿Cómo marcas los parámetros en un informe de Quarto?">
	En un bloque de código con la opción `tags: [parameters]`, que contiene los
	valores por defecto.
</Checkpoint>

<Checkpoint question="¿Qué opción define un parámetro en la línea de comandos?">
	`-P nombre:valor`.
</Checkpoint>

<Checkpoint question="¿Por qué usar --output al generar varias versiones?">
	Para que cada generación tenga su propio nombre de archivo y no sobrescriba
	las demás.
</Checkpoint>
