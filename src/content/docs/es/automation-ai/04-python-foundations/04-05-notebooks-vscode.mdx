## Por qué importa

Un **notebook** mezcla código, resultados y notas en un solo documento. Ejecutas el
código en pequeñas piezas llamadas celdas y ves el resultado debajo de cada una. Es
ideal para explorar datos, porque ves el efecto de cada paso. También es donde muchos
principiantes se confunden, así que ayuda aprender primero las reglas.

<CaseStudy>
	Daniela quiere mirar el archivo de ventas paso a paso: primero las columnas,
	luego unas cuantas filas y después las categorías. Un notebook le permite ver
	cada resultado antes de seguir.
</CaseStudy>

## Celdas, kernels y orden

- Una **celda** es un bloque de código (o de texto) que ejecutas por separado.
- Un **kernel** es el proceso de Python en ejecución detrás del notebook. Mantiene las
  variables en memoria entre celdas.
- Las celdas se pueden ejecutar en **cualquier orden**, y el kernel recuerda lo que se
  ejecutó, no el orden de la página.

Este último punto causa la trampa clásica: ejecutas la celda 3, luego la 1, luego la 2, y
tu notebook muestra resultados que nadie puede reproducir de arriba hacia abajo.

## Configúralo en VS Code

1. Instala la extensión **Jupyter** (del publicador Microsoft).
2. En tu proyecto, añade el paquete del kernel: `uv add --dev ipykernel`.
3. Crea un notebook con la paleta de comandos: **Create: New Jupyter Notebook** (Crear:
   nuevo Jupyter Notebook).
4. Arriba a la derecha, elige **Select Kernel** (Seleccionar kernel) y luego el entorno de
   Python de la carpeta `.venv` de tu proyecto.

Escribe código en una celda y ejecútala con el triángulo, o presiona **Shift+Enter**.

## Un script con estilo de notebook

También puedes escribir celdas dentro de un archivo `.py` normal, marcando cada una con
`# %%`. Con la extensión Jupyter, VS Code muestra **Run Cell** (Ejecutar celda) encima de
cada una. Así el archivo sigue siendo legible para Git y para cualquier Python.

<Example file="part04/05_explore.py" />

La salida de abajo es lo que ocurre si el archivo completo se ejecuta de arriba hacia
abajo. En un notebook verías cada parte debajo de su celda.

## Hábitos que mantienen honestos a los notebooks

1. **Reinicia y ejecuta todo** (Restart and Run All) antes de confiar en un resultado.
   Esto borra la memoria y ejecuta cada celda en orden.
2. Mantén las celdas cortas y en orden lógico.
3. No dependas de una celda que está mucho más abajo.
4. Ponle nombres claros a las cosas. Pregúntate qué necesita cada celda de las anteriores.

## Errores comunes

- **Ejecutar celdas en desorden.** Usa Restart and Run All para comprobarlo.
- **Estado oculto.** Una variable borrada del código puede seguir existiendo en la memoria.
- **Elegir el kernel equivocado.** Parece que faltan paquetes. Selecciona el `.venv` del proyecto.
- **Hacer commit de un notebook con salidas grandes.** Vuelve ruidoso el historial de Git.
- **Usar un notebook para la automatización final.** Consulta la lección 4.7.

<Checkpoint question="¿Por qué pueden ser difíciles de reproducir los resultados de un notebook?">
