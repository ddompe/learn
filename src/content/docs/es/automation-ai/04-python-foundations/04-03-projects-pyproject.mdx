## Por qué importa

Un **proyecto** de Python es una carpeta con tu código más una descripción de lo que
necesita. Esto permite que el proyecto funcione igual en tu laptop, en la de un colega y
en un servidor. Sin proyectos, los paquetes se acumulan en un solo lugar compartido, y
tareas distintas necesitan versiones distintas que entran en conflicto.

## Crea un proyecto

En una terminal, muévete a la carpeta donde guardas tus proyectos y ejecuta:

```text
uv init cafe-report
cd cafe-report
```

uv crea una carpeta con unos pocos archivos:

| Archivo           | Qué es                                                                        |
| ----------------- | ----------------------------------------------------------------------------- |
| `pyproject.toml`  | La descripción del proyecto: nombre, versión, versión de Python, dependencias |
| `main.py`         | Un programa inicial                                                           |
| `.python-version` | La versión de Python que usa este proyecto                                    |
| `README.md`       | Un lugar para describir el proyecto                                           |

También prepara la carpeta para Git. Si tu carpeta ya es un repositorio, no hay
problema.

## Lee pyproject.toml

**TOML** es un formato de texto para configuraciones. Tiene `[secciones]` y líneas
`nombre = valor`. Viste un ejemplo en la lección 3.8.

<Example file="part03/08_pyproject_example.toml" />

Lo editarás pocas veces a mano. Comandos como `uv add` lo cambian por ti.

## Añade un paquete

```text
uv add pandas
```

Esto hace tres cosas:

1. Añade `pandas` a las `dependencies` de `pyproject.toml`.
2. Crea un **entorno virtual**, en una carpeta oculta llamada `.venv`, e instala allí el
   paquete.
3. Escribe `uv.lock`, un registro de las versiones exactas (lección 3.8).

Un **entorno virtual** es una carpeta privada de paquetes para un proyecto. Dos proyectos
pueden usar versiones distintas sin chocar. Nunca editas `.venv` a mano y no haces commit
de ella en Git.

## Comparte un proyecto

Haz commit de `pyproject.toml`, `uv.lock`, `.python-version` y tu código. No hagas commit
de `.venv`. Añádela a `.gitignore` (lección 3.7). Un colega entonces clona el
repositorio y ejecuta:

```text
uv sync
```

que recrea el entorno a partir del archivo de bloqueo.

## Manos a la obra

### Ejemplo resuelto

1. Crea el proyecto con `uv init cafe-report` y abre la carpeta en VS Code.
2. Abre `pyproject.toml`. Encuentra el nombre, la versión de Python y la lista de dependencias.
3. Ejecuta `uv add pandas`. Mira `pyproject.toml` otra vez, luego encuentra `uv.lock` y `.venv`.
4. Añade `.venv/` a `.gitignore` y haz un commit.

## Errores comunes

- **Trabajar fuera de la carpeta del proyecto.** Ejecuta los comandos de uv dentro del proyecto.
- **Hacer commit de `.venv`.** Es grande y específica de cada máquina.
- **Editar el archivo de bloqueo a mano.** Deja que uv lo escriba.
- **Mezclar pip.** Usa `uv add`. Mezclar herramientas lleva a confusión.
- **Copiar la carpeta `.venv` a otra computadora.** Usa `uv sync` en su lugar.
