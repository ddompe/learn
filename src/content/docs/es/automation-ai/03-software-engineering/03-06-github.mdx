## Por qué importa

Hasta ahora, tu historial vive en una sola computadora. **GitHub** es un sitio web que
aloja repositorios de Git. Tener una copia allí te da una copia de seguridad, una forma
de trabajar desde otra computadora y una forma de trabajar con otras personas. También
es donde vive la mayor parte del software de código abierto.

Git y GitHub son cosas distintas. Git es la herramienta que registra el historial.
GitHub es un servicio que almacena repositorios.

## Local y remoto

Un **remoto** es una copia del repositorio en otro lugar, aquí en GitHub. Le envías
commits con **push** y traes commits nuevos de él con **pull**.

## Crea un repositorio privado

1. Inicia sesión en [https://github.com](https://github.com) (la cuenta de la lección 3.3).
2. Crea un **nuevo repositorio** (New repository). Dale un nombre sencillo, como `cafe-central`.
3. Elige **Private** (Privado). Solo tú (y las personas que invites) pueden ver un
   repositorio privado.
4. Por ahora, no marques las opciones para añadir un README, una licencia o un
   `.gitignore`.

**Advertencia:** un repositorio público lo ve todo el mundo y los buscadores lo indexan.
No publiques datos de clientes ni secretos. Ante la duda, elige Privado.

## Envía desde VS Code

En la vista de Control de código fuente (Source Control), elige **Publish Branch**
(Publicar rama) o **Publish to GitHub**. VS Code te pide iniciar sesión en GitHub en el
navegador y luego elegir un nombre y si el repositorio es privado o público. Elige
privado. Tus commits aparecen en github.com.

O desde la terminal, usando la dirección que GitHub muestra en la página del nuevo
repositorio:

```text
git branch -M main
git remote add origin https://github.com/YOUR-NAME/cafe-central.git
git push -u origin main
```

A partir de entonces, `git push` envía los commits nuevos y `git pull` trae los cambios
hechos en otro lugar.

## Ramas y pull requests

Una **rama** (branch) es una línea de trabajo separada dentro del mismo repositorio.
Puedes probar un cambio en una rama sin tocar la línea principal. Un **pull request** es
una solicitud en GitHub para combinar una rama con la línea principal, de modo que otras
personas puedan revisarla antes.

Cuando trabajas solo, a menudo haces commit directamente en `main`. En los equipos, un
pull request es la forma en que se revisan los cambios. No los necesitas ahora, pero verás
estas palabras por todas partes.

## Errores comunes

- **Crear un repositorio público por accidente.** Revisa la visibilidad antes de hacer clic en
  crear. Puedes cambiarla después, pero lo que estuvo público pudo haberse copiado.
- **Enviar secretos o datos personales.** Borrarlos después no los elimina del
  historial (lección 3.7).
- **Confundir Git con GitHub.** Uno es la herramienta, el otro el servicio de alojamiento.
- **Pegar una contraseña para hacer push.** Usa el inicio de sesión por navegador que ofrece VS Code.
- **Olvidar hacer push.** Los commits se quedan en tu computadora hasta que los envías.
