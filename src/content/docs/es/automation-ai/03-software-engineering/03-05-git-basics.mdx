## Por qué importa

Git solo ayuda si lo usas. Esta lección te lleva por todo el ciclo básico en una
carpeta real: avisarle a Git de un proyecto, cambiar algo, registrar el cambio y mirar
hacia atrás. También es tu red de seguridad para el trabajo con Copilot de la lección
3.3.

## Instala Git

VS Code usa Git, pero no lo incluye.

<OsTabs>
	<Fragment slot="windows">
		Descarga **Git for Windows** desde
		[https://git-scm.com](https://git-scm.com), ejecuta el instalador y acepta
		las opciones predeterminadas. Luego abre una terminal nueva y ejecuta `git
		--version`.
	</Fragment>
	<Fragment slot="macos">
		Abre Terminal y ejecuta `git --version`. Si falta Git, macOS ofrece instalar
		las herramientas de línea de comandos para desarrolladores. Acepta, espera a
		que termine la instalación y ejecuta el comando otra vez.
	</Fragment>
</OsTabs>

Deberías ver un número de versión. Recuerda la lección 1.10: si la terminal dice "not
found" (no se encuentra), abre una ventana de terminal nueva después de instalar.

Ahora dile a Git quién eres. Escribe este nombre en cada instantánea. Usa tu nombre y un
correo electrónico que no te importe tener en el historial.

```text
git config --global user.name "Daniela Mora"
git config --global user.email "daniela@example.com"
```

## Tres lugares

Git piensa en tres lugares.

<Mermaid
	diagram={`flowchart LR
  A["Carpeta de trabajo: tus archivos tal como están ahora"] -->|"preparar (stage)"| B["Área de preparación: los cambios por registrar"]
  B -->|"commit"| C["Historial: instantáneas guardadas"]`}
/>

- La **carpeta de trabajo** contiene tus archivos, tal como los editas.
- El **área de preparación** (staging area) contiene los cambios que elegiste para la
  siguiente instantánea. Tú decides qué entra, así que cada instantánea cuenta una sola
  historia clara.
- Un **commit** es una instantánea guardada en el historial, con un **mensaje de
  commit**.

## El ciclo en VS Code

1. Abre la carpeta en VS Code (lección 3.2).
2. Haz clic en el ícono de **Source Control** (Control de código fuente) en la barra
   izquierda y elige **Initialize Repository** (Inicializar repositorio).
3. Los archivos aparecen en una lista de cambios. Pasa el cursor sobre un archivo y haz
   clic en el **+** para prepararlo (stage), o prepara todos.
4. Escribe un mensaje en el cuadro, como `Add the January sales data`, y haz clic en
   **Commit**.
5. Edita un archivo y el cambio vuelve a aparecer en la lista. Prepáralo y haz commit de
   nuevo.
6. Haz clic en un archivo modificado para ver el **diff**, que muestra las líneas
   eliminadas en rojo y las añadidas en verde.

## El mismo ciclo en la terminal

```text
git init
git status
git add cafe_central_sales.csv
git commit -m "Add the January sales data"
git log --oneline
```

- `git init` convierte la carpeta en un repositorio.
- `git status` muestra qué cambió y qué está preparado.
- `git add` prepara un archivo.
- `git commit -m` guarda la instantánea con un mensaje.
- `git log --oneline` lista el historial, una línea por commit.

VS Code y la terminal son dos vistas de lo mismo. Puedes mezclarlas.

## Buenos mensajes de commit

Un mensaje debe decir qué y por qué, en una línea corta que complete la frase "Este
commit va a...":

- Bueno: `Fix duplicate rows in January totals`
- Malo: `update`, `stuff`, `final`

## Manos a la obra

### Ejemplo resuelto

1. En VS Code, abre la carpeta de Café Central.
2. Inicializa el repositorio y haz un primer commit que contenga los archivos de datos.
3. Crea un archivo `notes.md` que diga "Dates come in three formats." Prepáralo y haz
   commit con un mensaje claro.
4. Abre el historial con `git log --oneline` en la terminal y encuentra los dos commits.

### Ahora tú

Cambia el archivo de notas añadiendo una segunda línea. Antes de hacer commit, abre el
diff.

1. ¿De qué color es la línea nueva?
2. ¿Qué pasa si haces commit sin preparar primero?

<Checkpoint question="Muestra las respuestas">

1. Verde.
2. En VS Code te pregunta si quieres preparar todos los cambios y hacer commit. En la terminal no se confirma nada, porque el área de preparación está vacía.

</Checkpoint>

## Errores comunes

- **No instalar Git.** Control de código fuente muestra un mensaje de que falta Git.
- **Hacer commit de todo con el mensaje "update".** Tu yo del futuro no sabrá qué contiene. Escribe la razón.
- **Hacer commit de secretos o datos privados.** Revisa lo que preparas (lección 3.7).
- **Hacer un único commit gigante al final.** Los commits pequeños son más fáciles de entender y de deshacer.
- **Entrar en pánico por un comando que no entiendes.** Ejecuta primero `git status`. No cambia nada.
